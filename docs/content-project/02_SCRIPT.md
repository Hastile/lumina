# 대본 — 쇼츠·롱폼·제목·TTS·편집 인계

공통 문체·근거·수정 권한은 01만 따른다. 이 문서는 포맷 차이와 산출물만 정한다.

## 1. 공통 작업 흐름

확보된 조사와 사용자 수정 확인 → 영상의 질문 한 줄 → 필요한 근거 선택 → 보여줄 순서로 대본 작성 → 한 줄씩 검수 → 낭독본과 화면 지시 분리 → 승인된 범위의 음성·편집으로 연결한다. 중간마다 형식적인 승인을 받는 절차가 아니다. 이미 확정된 단계는 재작성하지 않는다.

괄호는 기본적으로 미낭독 각주·TMI·자료 메모다. '(표현 수정)', '(사실 확인)'처럼 사용자 작업 지시이면 지시로 처리한다. `[화면: …]`, 자료 메모, 오디오 태그는 낭독 본문과 분리한다. 괄호를 낭독에 끼워 넣어 리듬을 평가하지 않는다.

대본 확정 전에 핵심 화면이 확보 가능한지 확인한다. 초안에서는 근거·문장을 조정할 수 있지만 확정 내레이션을 편집 단계에서 소스 부족 때문에 임의로 지우지 않는다. 필요한 장면과 미해결 상태를 큐 ID로 남긴다.

## 2. 쇼츠

### 질문과 흐름

한 영상에서 답할 질문을 하나로 잡는다. 첫 화면과 첫 1~3초에 무엇을 보라는지 이해되어야 한다. 질문은 넓게, 답은 구체적으로 쓴다. 낯선 기술명·용어부터 설명하지 말고 보이는 현상이나 인물을 통해 들어간다. 팬이 아는 설정을 새로운 발견처럼 포장하지 않는다.

흔한 흐름은 훅 → 필요한 전제 → 해부 → 답이지만 빈칸 양식은 아니다. 전제는 결론에 쓸 재료만 남긴다. 전제가 필요 없으면 본론으로 간다. 비교·나열·참여형도 가능하다. 실제 반전이 없으면 통념을 지어내 뒤집지 않는다. '호평도 비판도 있다'는 구체적인 어긋남이 아니다.

흥미롭지만 질문과 무관한 정보는 다른 영상으로 돌린다. 결론에서 쓰지 않을 소개·줄거리·역사 설명을 덜고, 화면이 보이는 순서와 발화 순서를 맞춘다. 답을 낸 뒤 더 약한 감상이나 같은 결론을 붙이지 않는다. 참여형은 의도한 질문으로 끝낼 수 있다. 기본적으로 인사·자기소개·채널명·구독 좋아요 요청은 넣지 않는다.

확정된 나열 목록은 인원수·등장 순서·마지막 고정 인물까지 잠금으로 취급한다. 압축 전후와 TTS 인계 때 목록을 대조해 누락·교체·중복이 없는지 확인한다. 분량을 줄이려고 인물을 임의로 빼지 않는다.

### 길이와 낭독

실제로 낭독할 본문만 공백 포함 글자 수를 계산한다. 약 **7.5자/초**는 제작 전 예상 길이 참고값이다. 30초 약 230자, 40초 약 300자, 50초 약 380자 정도이며 실제 녹음이 있으면 음성 길이가 우선한다. 미낭독 각주·화면 지시·태그는 제외한다. 30초면 끝날 내용을 40초로 늘리지 않는다. 이 수치로 자막 타이밍을 비례 배분하지 않는다.

### 제목·영상 타이틀·고정댓글

- 업로드 제목은 질문·현상을 앞세운 말하듯 읽히는 한 줄이다. 과거 관찰상 10~25자가 많았으며 글자 수를 맞추기 위해 뜻을 망가뜨리지 않는다. 실제 내용에 있을 때만 부정·반전을 쓴다. 작품명만 바꿔 성과 제목을 복제하지 않는다.
- 요청 범위가 전체 제작이면 제목 3~5개와 추천 1개, 작품명 한글/영문·캐릭터·주제 태그를 제안한다. 부분 교정에 매번 붙이지 않는다.
- 영상 상단 카피는 별도다. 서브는 수식어·훅, 메인은 주제 명사로 두 줄이 한 명사구로 읽히게 한다. 서브 6~10자(최대 11), 메인 5~9자(최대 9)를 출발 기준으로 삼고 실제 템플릿 폭으로 검수한다. 조사·의미 덩어리를 잘라 줄을 바꾸지 않는다.
- 답 가리기는 답에 해당하는 한 단어만 음절당 `?` 하나로 가리고 조사는 남긴다. 내레이션이 그 단어를 처음 말할 때 공개한다.
- 고정댓글은 영상에서 들은 내용과 연결되는 추가 근거 하나다. 정확한 인용·근거 목록·짧은 보충 중 자료에 맞는 형식을 고른다. 모르는 사람 이름부터 시작하지 않고 출처는 뒤에 둔다. 기사 요약 말투·무관한 소식·영상과 모순되는 보충을 피한다. 한 댓글 안 말투를 맞춘다. 초안 작성과 실제 게시를 구분한다.

### 기본 산출물

대본 → 영상이 하는 말 한 줄 → 실제 낭독 글자 수/예상 길이 → 사실 확인·화면 확보 미해결 → 제목 후보/태그 → 자료가 있을 때 고정댓글 초안. 사용자가 '대본만' 또는 부분 수정을 요청하면 그 범위만 낸다. 메타 설명이 대본보다 길어지지 않게 한다.

## 3. 롱폼

### 도입

기본 도입은 눈에 보이는 현상 하나 → 어긋나는 확인 사실 → 질문 하나 → **'이번에는/오늘은 ○○가 어떻게 디자인되었는지 알아보겠습니다'**다. 원본의 4~6문장·150~300자는 기본 분량 참고이며 문장을 억지로 늘리는 목표가 아니다. 비평형은 '하나하나 짚어보겠습니다' 같은 짧은 진입을 쓴다.

채널의 고정 진입 문장은 정보 없는 진행 멘트를 줄이는 규칙의 예외로 유지한다. '디자인·마케팅·반응까지 살펴보겠다'는 작업 목차를 덧붙이지 않는다. 로고·스포일러 안내는 이 도입 뒤에 둔다. 도입은 본문의 요약이나 발표 목차가 아니다.

여러 주역·작품 단위라면 전체를 묶는 사실로 연다. 한 명으로 시작해 그 인물만 다루는 영상처럼 만들지 않는다. 같은 질문을 표현만 바꿔 반복하거나 기준 없는 인기·흥행 비교를 훅으로 쓰지 않는다. 결말은 스포일러 안내 전에 공개하지 않는다. 관계·구성 수준의 민감한 공개는 사용자 지정 스포일러 범위를 따른다. 범위가 불명확하면 공개를 보류하고 필요한 범위를 확인한다.

### 본문

첫 본론은 강한 디자인·장면·비교처럼 눈에 보이는 재료다. 그 뒤 왜 그렇게 만들었는지 역추적하고 실제 구현·시장 전개·반응으로 연결한다. 연구 보고서 목차를 낭독 순서로 옮기지 않는다.

기본 연결: 디자인/서사 선행 → 비전 → 경쟁·포지셔닝 → 브랜드 아이덴티티 → 컨셉/톤앤매너 → 디자인/서사 회수 → 마케팅 → 피드백. 작품의 질문에 맞게 순서를 바꿀 수 있다. 모든 구간을 억지로 채우거나 모든 캐릭터에 같은 틀을 반복하지 않는다.

- 세부가 다음 질문을 부르게 한다. 개념은 사례·대비 뒤에 붙이고 일상어 판정으로 묶는다. 이미 답한 구간의 요소를 또 나열하지 않는다.
- 줄거리는 디자인을 다시 볼 만큼만 쓴다. 사건을 순서대로 옮기지 않는다. 비슷한 인물 나열보다 익숙한 주요 인물과의 대비 한 축이 낫다.
- 여러 주역은 관계축으로 묶고, 인물별로 설명할 가치가 큰 부분을 달리한다. 작품 단위의 비전·마케팅·피드백은 한 번 다룬다. 조연은 주역 이해에 필요한 범위만 쓴다.
- 앞서 본 외형을 서사 뒤에 다시 볼 때는 새 정보가 생겨야 한다. 이미 설명한 외형을 브랜드 아이덴티티 장에서 재정의하지 않는다. 영상 샷 재사용은 03의 엄격한 기준을 별도로 통과해야 한다.
- 마케팅은 일정·형식·성우 이름 나열이 아니라 그 선택이 설계를 어떻게 전하고 시청자에게 무엇을 남겼는지 다룬다. 피드백은 인지도·선호·매출·지속성과 원인을 구분한다.
- 비판은 특정 장면·문구·관계·전개에 근거한다. 디자인 분석에서 결론을 먼저 정해 모든 요소를 몰아가지 않는다. 무거운 상실·치료·죽음 구간에 가벼운 농담을 덧붙이지 않는다.

### 마무리

도입 질문의 답은 본문 회수와 피드백의 마지막 판정에서 완결한다. 그 뒤 영상 전체를 다시 요약하는 별도 결론을 읽지 않는다. 마지막은 팬이 자기 해석을 붙일 수 있는 댓글 질문 하나와 구독 안내다.

기본 문형: '여러분은 ○○의 어떤 점이 가장 마음에 드셨나요? 댓글 남겨주시면 다음 영상 제작에 큰 도움이 됩니다. 이 영상을 재밌게 보셨다면 구독 좋아요 알림 설정 눌러주세요.' 대상과 실제 질문에 맞추되 확정 문장은 보호한다. 쇼츠의 CTA 생략 기준을 롱폼에 적용하지 않는다.

### 초안과 확정본

초안은 자료 기준일·스포일러 범위를 머리에 쓰고 `## 0. 도입`처럼 장을 나눈다. `[화면: …]`와 `> 자료 메모 — …`는 미낭독이다.

확정본은 장마다 **확정 내레이션 / 화면 큐**를 분리한다. 큐는 `00-01` 형식 ID, 진입 문구, 소스, 화면, 강조 자막, 보호할 요소·금지, 확보 상태를 담는다. 첫 문구가 들릴 때 시작하고 다음 큐까지의 범위를 의미 단위로 정한다. 음성이 나온 뒤 실제 시간으로 검증한다.

| 큐 등급 | 의미 |
|---|---|
| 필수·근거 | 비교·문구·수치 등 주장을 증명하는 화면. 장식으로 대체 불가 |
| 필수·장면 | 사건 이해에 필요한 실제 장면. 다른 사건으로 대체 불가 |
| 보조 | 배치·줌·효과음 등 조정 가능한 연출 |

폐기된 기획 메모는 현행 편집 큐와 분리하고 '폐기/참고'로 표시한다. 자료가 없으면 큐 ID와 문제를 남기며 확정 내레이션을 몰래 지우지 않는다.

## 4. TTS와 자막으로 넘기기

“그대로 TTS”는 요청한 태그 부착·제거 외 문구 변경 금지다. 최신 확정 원고와 TTS 입력·실제 음성 테이크를 대조하고 인원수·순서·고유명사·어미·마지막 문장 불일치를 명시한다. 실제 음성을 듣지 못했다면 입력 대조와 음성 대조를 구분한다. 불일치한 음성에 맞춰 확정 원고를 몰래 고치지 않는다.

확정 원문을 보존한 채 태그를 적용한다. 태그만 요청했다면 문구·어미·고유명사·순서를 바꾸지 않는다. 발음 문제는 별도 메모로 남기고 정식 표기를 몰래 바꾸거나 이름 중간에 쉼표를 넣지 않는다. 존재가 확인되지 않은 음성 도구나 태그 지원을 가정하지 않는다.

최신 원고와 사용한 음성 테이크를 연결해 보관한다. 음성 분석 입력에는 실제 읽은 내용만 넣고 TTS 태그·TMI·화면 지시를 제외한다. 문장 줄바꿈·화면 안 개행·시간상 자막 분할은 서로 다르다. 최종 시간은 실제 음성과 프레임으로 맞추며 7.5자/초 추정으로 자막을 정렬하지 않는다.


화면용 자막을 만들 때는 원고의 문장부호·문단을 그대로 화면 분할로 사용하지 않는다. 원본 낭독 대본은 보존하고 별도 캡션에서 끝 쉼표·마침표 정리, 의미 단위 시간 분할을 수행한다. 현행 script는 입력 줄을 출발점으로 자동 후처리에서 긴 행을 분할할 수 있다. 의미 분할의 정확성은 preview에서 검수한다. 자막 표시·타이밍의 완료 기준은 03/04를 따른다.
