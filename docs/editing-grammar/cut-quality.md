# 컷·프레임 튐의 판정과 보정

2026-10-31 사용자 요청을 기준으로 정의한 작업 용어다. 모든 업계 용례를 하나로 제한하는 표준 정의는 아니다.

**컷이 튄다**: 의도한 정보·동작·시선·리듬의 연결보다 화면 변화 자체가 먼저 인지되어 설명을 방해하는 편집 결과. 정상적인 하드 컷이나 큰 화면 변화 자체는 결함이 아니다.
**프레임이 튄다**: 프레임 단위에서 의도하지 않은 영상·위치·밝기·시간 진행의 불연속이 나타나는 현상. 다른 샷 혼입, 검은/흰 프레임, 잘못된 소스 매핑과 렌더 문제가 원인일 수 있다. 정상적인 애니메이션 홀드·반복 프레임을 드롭으로 단정하지 않는다.

## 원인별 판정

| 분류 | 엄밀한 판정 근거 | 보정 |
|---|---|---|
| 다른 샷 혼입 | 선택한 소스 구간의 처음/끝 또는 내부에 의도하지 않은 다른 샷이 표시 프레임 1개 이상 존재. DB 대표 이미지가 같아도 제외 불가 | 실제 전환 프레임을 찾고 out을 다른 샷의 첫 프레임 직전까지로 제한. [in,out)에서 out은 제외되므로 다른 샷 첫 프레임을 out으로 설정. 앞쪽 혼입은 in 이동. 필요한 타임라인 길이는 인접 샷·대체 소스로 다시 설계 |
| 인지 시간 부족 | 해당 컷의 대상·근거를 알아보기 전에 교체되어 순간 삽입처럼 보임. 꼭 필요한 장면이어도 발생. 고정 초수·프레임 수만으로 확정 불가 | 같은 샷의 깨끗한 여유 구간 확보, 주변 컷 길이 재배분, 더 잘 읽히는 소스/인서트 구성. 무조건 삭제·슬로모션·중복 재사용 금지 |
| 끝무렵 동작 돌출/미완결 | 설명용으로 유지하던 샷에서 끝 직전 새 동작·팬·줌·표정 변화가 시작되어 주의를 끌지만, 이해 가능한 진행/결과 없이 다음 컷으로 끊김 | 동작 시작 전 안정 구간에서 종료하거나 동작의 이해 가능한 단계까지 유지. 필요한 동작이면 다른 각도로 이어 행동 연속성 확보. 모든 움직임을 제거하거나 양 끝을 같은 이미지로 만들지 않음 |
| 연결 불일치 | 각 샷은 적절해도 연결점에서 대상 위치·크기·시선·운동 방향 또는 시간 진행이 설명과 무관하게 충돌 | 전후 프레이밍·동작 위상·컷 위치 조정, 근거 있는 다른 샷 사용. 같은 인물이라는 이유만으로 연결 승인 금지 |
| 출력 프레임 이상 | 원본은 정상인데 합성/출력에 검정·섬광·중복·누락·잘못된 소스 프레임이 나타남 | fps·속도·리타이밍·레이어·전환·렌더 경로 구분 진단. 원본 트림으로 숨기지 않음 |

의도된 짧은 리액션, 행동 중 매치 컷, 충격을 위한 불연속은 예외가 될 수 있다. 의도와 정상 속도 확인 근거를 남긴다. 두 끝 이미지가 비슷하다는 사실은 중간에 다른 샷이 없거나 동작이 자연스럽다는 증거가 아니다.

## DB → 원본 → 합성 → 연속 시청

1. `source_search`/`source_cut`으로 후보와 사용 이력·분석 상태를 읽는다. DB 구간·인물·설명은 후보 근거이며 정답 보증이 아니다. 이미 분석된 항목은 재사용하고 누락 정보만 분석한다.
2. 대표 이미지는 후보 선별용이다. 선택 범위 전체를 훑고, 모든 의심 전환과 in/out 근처는 `inspect_source_frames`로 **step=1 연속 프레임**을 확인한다. 한 번에 최대 24개이므로 필요한 범위를 이어 조회한다. coarse sampling에서 안 보였다는 이유로 1프레임 혼입 없음 판정 금지.
3. 소스 프레임 번호는 0부터 시작하는 표시 순서다. 타임라인 프레임 번호와 별개다. 23.976/29.97, VFR, 속도·역재생·중첩을 무시한 초×30 계산 금지. VFR은 반환 PTS를 읽고, 실제 배치 후 합성을 다시 확인한다. out은 제외: 마지막 사용 프레임과 첫 제외 프레임을 구분한다.
4. 배치할 때 의미 경계와 실제 음성에 맞춘다. 자막 한 장마다 컷을 강제하지 않는다. 목적 구간·소스 범위·속도·설명 근거·재사용 이유를 기록하고 트랜잭션으로 적용한다. 깨끗한 구간이 짧으면 다른 구성으로 해결하며 혼입 프레임까지 늘리지 않는다.
5. `inspect_timeline_frames`에 명시한 sequence_id와 경계 전후 프레임 번호를 주어 최종 합성을 검수한다. 소스 검사만으로 합성까지 통과 처리하지 않는다. 끝무렵 동작은 마지막 한 장이 아니라 이전의 안정 상태부터 시작·진행을 함께 본다.
6. 동작·리듬·인지 시간은 앞뒤 내레이션과 함께 정상 속도로 재생/출력해 확인한다. 연속 정지 이미지도 정상 속도 시청과 동일하지 않다. 시청 능력이 없는 환경에서는 그 검수는 미완료로 남기고 사용자에게 정확한 구간을 지정한다.
7. 검수 기록: 시퀀스/클립 ID, 소스 경로·프레임/PTS, 타임라인 경계, 분류, 관찰 근거, 수정 전후 in/out, 정상 속도 확인 여부, 남은 불확실성. 수정 뒤 영향받은 양쪽 경계를 재검사한다.

도구의 `mean_rgb_change`는 축소 RGB 평균 절대 차이(0~1)다. 얼굴/샷 식별·광학 흐름·동작 완료 판정이 아니다. 높아도 정상 액션·플래시일 수 있고 낮아도 비슷한 구도의 다른 샷일 수 있다. 자동 합격 점수나 일괄 트림 임계값으로 쓰지 않는다. `complete=false`는 요청 프레임을 전부 얻지 못했다는 뜻이며, `complete=true`도 요청 범위를 얻었다는 뜻일 뿐 품질 합격이 아니다.
