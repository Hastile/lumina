# 영상 편집 — 컷·소스·자막·화면·소리·검수

쇼츠와 롱폼의 공통 판단은 이 문서에 둔다. 대본 구조·문체는 01/02, 도구 호출·파일 처리는 04를 따른다. 아래 수치는 포맷별 사용자 기본값과 과거 관찰을 구분해 적용하며 실제 프로젝트·사용자 수정이 우선한다.

## 1. 확정 대본을 컷 계획으로 바꾸기

샷의 기본 단위는 자막 한 장이 아니라 **설명 대상 + 주장/행동 + 필요한 증거**다. 자막 교체·마침표·음악 박자는 자동 컷 명령이 아니다. 한 행동을 여러 자막에 걸쳐 유지할 수 있고, 새 주어·나열 항목·이름 공개·사건·논점이 나오면 새 화면이 필요할 수 있다.

놓기 전에 큐별로 다음을 적는다.

| 큐 ID/구간 | 확정 내레이션·진입 문구 | 대상·주장 | 실제 소스와 in/out | 먼저 볼 증거 | 유지/컷 이유 | 재사용 여부·이유 | 자막·소리 | 검수·미해결 |
|---|---|---|---|---|---|---|---|---|

관련 클립을 읽고 실제 fps로 배치한다. 수식어와 대상, 목적어와 동사, 준비와 결과를 무의미하게 분리하지 않는다. 행동은 결과를 인지할 때까지, 읽기 자료는 읽을 때까지 유지한다. 긴 샷 자체를 리듬 부족으로 판단하거나 일정 초마다 줌·컷을 넣지 않는다.

소스는 직접적인 행동·표정·디자인·문서 증거 → 정확한 중립 샷/정지 이미지 → 비교 자료/도식 순으로 찾는다. 파일명·DB 설명은 단서일 뿐 실제 구간을 확인한다. 특정 사건을 다른 사건의 장면으로 대체하지 않는다. 정답을 숨기는 도입에서는 얼굴·이름·결과 공개 시점을 지킨다.

## 2. 중복 장면은 정말 신중하게 재활용

**사용자 확정(2026-10-31): 초안에 같은 장면으로 때운 듯한 편집이 많이 보였다. 초안부터 이 기준을 적용한다.**

- 이미 쓴 장면을 편한 기본 소스로 삼지 않는다. 같은 인물이 나오거나 길이가 맞는다는 이유는 재사용 근거가 아니다.
- 최초 사용 위치·당시 역할·이번에 새로 볼 근거·다른 소스보다 꼭 필요한 이유를 적는다. 구체적으로 설명할 수 없으면 다른 소스나 구성을 찾는다.
- 회상·전후 비교·복선 회수·같은 사건의 다른 세부 검증처럼 다시 보여주는 행위 자체가 설명에 기여할 때만 검토한다. '강조/분위기/소스 부족'이라는 명칭으로 정당화하지 않는다.
- 크롭·줌·반전·속도 변경·몇 프레임의 in/out 차이는 새 증거가 아니다. 같은 파일의 다른 구간이라도 실질적으로 같은 행동·구도면 중복 후보이며, 같은 파일 속 별개 사건을 파일명만으로 중복 판정하지도 않는다.
- 부족하면 다른 실제 장면·정지 이미지·비교 자료·도식을 찾거나 적합한 샷을 자연스럽게 유지한다. 못 찾으면 미해결로 남긴다. 무관한 영상이나 반복 샷으로 채워 완료 처리하지 않는다.
- 최초 사용과 반복 사용을 앞뒤 내레이션까지 비교 재생한다. 새 정보 없이 장면만 다시 시작되거나 때운 느낌이면 교체한다. 반복 횟수·간격에 기계적 허용치를 만들지 않는다.

## 3. 구도·연출·경계

한 순간에 먼저 볼 대상이 분명해야 한다. 배경 전환·큰 글자·줌·화살표·효과음을 동시에 터뜨리지 않는다. 화면의 기존 강조가 충분하면 새 강조를 생략한다.

작은 세부는 전체 맥락 → 관찰 위치 안내 → 확대 → 읽기 유지로 보여준다. 여백·인물 간 거리·화면비가 증거면 전체 구도를 보존한다. 비교는 키의 발 기준선, 머리 형태의 확대율 등 논점에 맞는 축으로 맞춘다. 기획표 전체를 작게 띄우지 말고 지금 비교하는 항목만 보이게 한다.

누적 비교는 이미 이해한 항목을 남겨 두고 새 항목만 추가할 수 있다. 현재 항목의 대비를 높이고 끝에는 비교 시간을 준다. 카드의 역할을 읽기/회상/분위기로 구분한다. 회상 카드에 새로운 논거를 숨기거나 모든 내용을 읽히려고 영상 전체를 무작정 늘리지 않는다.

카메라 이동은 추적·공개·관찰 안내의 목적이 있을 때만 쓴다. 주석·밝기 변경은 역할이 끝나면 걷어낸다. 설명용 합성·변형은 실제 원작과 구분한다. 원작 자체의 작화·연출을 채널이 추가한 효과와 혼동하지 않는다.

원본의 다른 장면이 한두 프레임 섞이지 않도록 컷 in/out과 소스 내부 전환을 확인한다. 흰 플래시·검은 페이드·디졸브·점프를 늘리기나 잘게 자르기로 숨기지 않는다. 문제 구간이나 소스를 바꾼다. 기본은 명확한 컷이며 전환은 시간·공간·챕터 관계를 설명할 때 쓴다.

속도는 100%에서 시작한다. 길이가 부족하면 소스 범위와 샷 설계를 먼저 바꾼다. 동작이 자연스럽고 목적이 있을 때만 조정한다. 사용자 액션 마커는 소스 시간과 시퀀스 시간을 구별해 맞추며, 단순 영상 길이 맞추기와 구분한다.

## 4. 자막·대본·그래픽

대본은 확정 낭독 내용, 캡션은 음성에 맞춘 화면 자막, 그래픽은 제목·이름표·강조·TMI다. 같은 긴 문장을 캡션과 그래픽 양쪽에 반복하지 않는다. 내레이션이 가리키는 부위·표정·숫자를 가리지 않는다.

시간상 자막 교체와 한 자막 안 줄바꿈을 구분한다. 문구·분할은 사용자의 최신 수정본을 보존한다. 글자 수 비례로 시간을 나누지 않고 실제 음성으로 정렬한다. 대본 정렬·재정렬에서는 앞 자막 끝을 다음 시작에 이어 **중간 빈 구간을 없앤다**. 일반 영상 첫 자막은 0프레임부터 표시하고 명시한 무자막 인트로는 별도 보정한다. 마지막은 실제 발화와 포맷별 끝 기준을 따른다. 자동 정렬 결과의 정확성은 별도로 검수한다.

Lumina 텍스트 패널은 모든 자막 트랙을 보여준다. Enter 분할, Shift+Enter 강제개행, 맨 앞 Backspace 이전 자막 병합을 사용한다. 병합은 같은 트랙의 이어지는 자막이며 스타일·효과가 다르면 거부된다. 음성 위치 정보가 없는 분할은 확인한 시각을 지정한다. 마침표·띄어쓰기·줄바꿈 수정은 음성 정렬 정보를 유지한다. 문구 자동 반영과 프로젝트 파일 저장은 별개다.

### 롱폼 기본값

- Pretendard Medium 60, 자간 -20, 박스 기본 폭 1440px. 호시노 완성본 시퀀스 09에서 확인한 박스는 1440×324다.
- 실제 폰트 폭·합성 결과를 기준으로 분할한다. 애매한 개행은 좌우 확장 가능하며 확장 상한·기본 허용 줄 수는 아직 확정하지 않았다. 박스 높이를 허용 줄 수로 해석하지 않는다.
- 30자/5초 등은 재검토 신호이며 자동 탈락 조건이 아니다. 긴 문구를 무조건 폰트 축소로 해결하지 않는다. 자간 -20을 다른 렌더러의 -20px로 복사하지 않는다.
- 위치는 프로젝트와 화면 내용에 맞춰 확인한다. 박스 좌상단 좌표와 점 텍스트 중심 좌표를 구분한다. 특정 프로젝트의 Y값을 공통 기본값으로 만들지 않는다.
- 쇼츠의 자막 밀도·효과 배분·120 강조를 롱폼에 일괄 적용하지 않는다.

## 5. 쇼츠 추가 기준

### 프로젝트·컷·프레이밍

- 작품 폴더의 기존 `.lumina` 안에서 복사용 시퀀스를 복제해 `시퀀스 02 (<제목>)`로 만든다. 쇼츠마다 새 프로젝트를 만들지 않는다. 원본 템플릿은 보존한다.
- 문장·절·공개 시점으로 묶고 컷 시작은 가능한 자막 시작에 맞춘다. 짧은 도입어는 다음 의미 구간과 한 샷으로 묶는다. 문장 꼬리 직전의 불필요한 컷, 연속된 1자막 1샷을 피한다.
- 사용자 수정에서 정해진 **1.1초 미만 샷을 만들지 않는 조건**을 유지한다. '2자막당 1컷', '4초면 반드시 컷', 과거 컷 비율은 규칙이 아니다. 사용자가 지정한 마커·연출이 우선하며 롱폼에 숫자를 복사하지 않는다.
- 기존 세로 템플릿에서 16:9 소스의 출발점은 위치 [540,1060], 스케일 115다. 작거나 치우친 인물은 130 이상 확대·X 이동을 검토하고, 자막에 얼굴이 가려지면 Y를 조정한다. 띠 창과 실제 화면을 검수한다. 비교 구도가 근거면 전체 화면 인서트도 가능하다.
- 속도는 100% 기본, 보통 미세 조정은 87~105%를 참고한다. 사용자 마커 정렬은 별도 목적이며 과거 관찰 범위를 강제로 맞추지 않는다. 느리게 늘려 결함을 숨기지 않는다.
- 끝은 내레이션 끝 + 6프레임 기준으로 V5 그래픽·V6 타이틀·마지막 자막을 맞춘다. 실제 fps와 사용자 지정 끝점을 확인한다.
- 소스 종류를 편의상 하나로 채우지 않는다. 영상·일러스트·설정화·실제 기사·비교 자료는 주장에 필요한 것을 고른다. 무관한 게임 그림, 거의 검은 샷, 가사 글자로 복잡한 샷, 홍보의 텍스트 전용 카드를 대체 장면으로 넣지 않는다.

### 캡션·TMI·타이틀

- 쇼츠도 화면용 자막 끝 쉼표·마침표를 기본 제거하며 원본 대본은 유지한다. 실제 음성의 어절·의미 경계와 화면 폭으로 분할을 검수한다. 자동 후처리는 후보 결과이며 고유명사·불완전 구문·의도한 문장부호는 확인한다.

- 실제 트랙 ID·이름·효과를 확인한다. 통상 V7 pop, V8 slam, V9 fade지만 번호만으로 편집하지 않는다.
- 기본 Pretendard-Bold 100, 흰색·어두운 외곽선. pop은 기본, slam은 핵심 구절, fade는 문장 꼬리의 차분한 마무리다. 비율을 맞추기 위해 효과를 배치하지 않는다.
- 강조는 개별 캡션 120을 기본으로 하되 810px 폭에 한 줄로 들어가는지 검수한다. 길면 100을 유지한다. 140/200·특수 폰트는 드문 명시적 연출 예외다.
- 문장 중간 fade는 대등한 사실을 마무리할 때 검토한다. 조건·양보·반전 준비절은 멈춤이 있어도 기본 pop을 유지한다. 긴 최종 서술어는 fade, 짧은 펀치 판정에만 마지막 slam을 검토한다.
- 발화가 너무 짧은 캡션(약 0.25초 미만)은 다음 의미 구간과 병합 검토한다. 이름이 이미 제목에 보인다고 모든 작품명 발화를 자동 삭제하지 않는다. 특정 자막 생략은 해당 사용자 지시 범위에서만 한다.
- TMI는 **한 개의 일반 영상 트랙 `TMI`(보통 V4)**의 그래픽 레이어다. 여러 TMI 캡션 트랙으로 늘리거나 본 자막을 그래픽으로 바꾸지 않는다. 동시 메모는 한 그래픽의 여러 레이어로 묶을 수 있다.
- TMI는 Pretendard-Medium 48, 박스 810×576, 세로 중앙 정렬. 기존 템플릿 좌상단 Y는 본 자막 100 위 680, 120 위 670, 아래 보충 960을 출발점으로 실제 합성을 확인한다. 본 자막 효과와 움직임을 맞춘다.
- TMI는 이름·원문 표기·수치 정정·짧은 원리·혼잣말·출처다. 명사구·메모체를 쓰고 본문 존댓말을 반복하지 않는다. 한 줄 7~19자, 처음/마지막 10%에 드문 배치는 과거 경향이며 개수 목표가 아니다. 실제 읽을 시간과 관련성이 우선한다.
- TMI는 원칙적으로 관련 본 자막 **하나의 시작·종료 프레임**에 맞춘다. 의도된 연출 외에는 두 자막 이상에 걸치지 않는다. 너무 짧으면 문구를 압축하거나 생략을 검토하며 습관적으로 다음 자막까지 늘리지 않는다. 본 자막이 재분할되면 관련된 한 조각에 다시 연결하고 시간·위치를 함께 검수한다.
- 이름 소개의 작품명은 캐릭터 이름이 처음 등장하는 자막 바로 위에 괄호로 표시한다. 변신체·별칭과 본명이 다르면 원래 인물명을 함께 표시할 수 있다. 기존 TMI 폰트·위치 기준 안에서 실제 합성으로 확인한다.
- 타이틀 문구는 02를 따른다. `?` 공개 시점·줄바꿈·폰트 폭을 실제 프레임으로 검수한다.

### 쇼츠 소리 기본값

효과음 배치 전에 최근 완성 쇼츠의 실제 사용 구간을 확인하고 후킹·새 인물·핵심 사건·마무리를 내레이션·자막·화면 변화와 함께 계획한다. 효과음이 없는 긴 구간도 적극 검토하되 무조건 채우지 않는다. 참고한 프로젝트/시퀀스·시각과 역할을 남기고 접근하지 못했다면 참고한 척하지 않는다.

소리보다 내레이션 이해가 우선한다. 사용자가 쓰는 팔레트 안에서 고르며 장면 테마를 이유로 낯선 마법음 등을 임의 도입하지 않는다.

| 역할 | 선택 기준 |
|---|---|
| Whoosh | 문장 시작·새 화면·발화 휴지. 문장 꼬리에는 붙이지 않음. W3는 시작 프레임, W4는 본론/결론 진입, W1/5/6 등은 맥락에 따라 순환 |
| Kick 2 | 이름·목록 카드. 모든 정지 이미지에 자동 부착하지 않음 |
| Kick 1 / Kick 5 | 설명 속 가벼운 개념·용어 / 후반 판정·정리 |
| Guns / Cash / Impactor | 정체·이름 공개 / 놀라운 사건 / 강한 반전·결정타 |
| Epic Hit 3 | 전환점. 약 0.7초(30fps 21프레임) 앞에서 시작해 타격이 자막에 맞도록 검수 |
| Bells 2 / 뚜훅 / 티딩 / 물방울 | 질문·궁금증 / 핵심·기이한 사실 / 납득·마무리 / 허탈·부정 |

기본은 자막 첫 프레임에 맞추며 한 자막당 한 소리, 소리 간 최소 0.5초를 지킨다. Whoosh 동일 파일을 연속 사용하지 않는다. fade는 대체로 무음이며 퍼센트나 평균 개수를 채우지 않는다. 같은 트랙의 꼬리 덮어쓰기를 확인한다. 같은 계열의 반복과 여러 소리의 꼬리 겹침도 확인한다. 원본의 시작 타격·끝 감쇠를 보고 구간을 고르며 짧은 시퀀스에 맞추려고 무조건 잘라 넣지 않는다. 개수 증가를 품질 향상 근거로 삼지 않고 최종 청감 미검수는 별도로 표시한다.

A2/A3/A4 트랙 페이더 -3dB, A5 BGM -6dB. Auto-Match는 A2/A3만, A4 Bells·물방울은 제외한다. 티딩·Kick 5·Epic Hit 2의 클립 Volume은 -3dB, 티딩 Gain은 -7dB 기준이다. Gain과 Volume, 트랙 페이더를 혼동하지 않는다.

BGM은 트랙 페이더 이후 단독 미터가 약 -24~-27dB 범위로 움직이는 기준이며 **LUFS가 아니다**. 실제 음원 구간을 측정하고 클립 Gain을 조정한다. 과거 특정 음원 Gain을 다른 곡에 복사하지 않는다.

## 6. 공통 소리·완료 검수

원작 대사 자체가 증거면 음성 주도권을 내레이션 → 원작 → 내레이션 복귀로 계획한다. 첫 음절·끝말·효과음 꼬리·급격한 음량 변화·말 겹침을 실제 청취한다. BGM은 논점·감정 흐름을 받치며 일정 분마다 곡을 바꾸지 않는다. 무거운 서사에서는 효과를 덜고 조용한 구간도 허용한다.

롱폼 첫 자동 편집은 도입·설명·비교가 들어 있는 60~90초 정도로 자체 검증한 뒤 확장할 수 있다. 새 승인 절차나 모든 영상에 강제하는 길이 규칙이 아니다.

최종 확인은 대상 일치, 실제 증거, 공개 시점, 정상 속도의 읽기·이해, 경계 프레임, 중복 샷의 필요성, 소리 명료도, 사용자 확정 문구·분할·스타일 보존이다. 긴 자막·여러 층 겹침·합성·교체 경계를 특히 본다. 표본 이미지·파형·LUFS 검사만으로 전체 시청·청취 완료라고 하지 않는다.

원본·레퍼런스는 해결하려던 목적을 배우고 결함은 재현하지 않는다. 호시노 기준은 `인계 파일/타카나시 호시노.prproj`의 `시퀀스 09`다. 컷 수·줌 수·효과음 수가 비슷해졌다는 이유로 합격시키지 않는다.

# 컷·프레임 튐의 판정과 보정

2026-10-31 사용자 요청을 기준으로 정의한 작업 용어다. 모든 업계 용례를 하나로 제한하는 표준 정의는 아니다.

**컷이 튄다**: 의도한 정보·동작·시선·리듬의 연결보다 화면 변화 자체가 먼저 인지되어 설명을 방해하는 편집 결과. 정상적인 하드 컷이나 큰 화면 변화 자체는 결함이 아니다.
**프레임이 튄다**: 프레임 단위에서 의도하지 않은 영상·위치·밝기·시간 진행의 불연속이 나타나는 현상. 다른 샷 혼입, 검은/흰 프레임, 잘못된 소스 매핑과 렌더 문제가 원인일 수 있다. 정상적인 애니메이션 홀드·반복 프레임을 드롭으로 단정하지 않는다.

## 원인별 판정

| 분류 | 엄밀한 판정 근거 | 보정 |
|---|---|---|
| 다른 샷 혼입 | 선택한 소스 구간의 처음/끝 또는 내부에 의도하지 않은 다른 샷이 표시 프레임 1개 이상 존재. DB 대표 이미지가 같아도 제외 불가 | 실제 전환 프레임을 찾고 out을 다른 샷의 첫 프레임 직전까지로 제한. [in,out)에서 out은 제외되므로 다른 샷 첫 프레임을 out으로 설정. 앞쪽 혼입은 in 이동. 필요한 타임라인 길이는 인접 샷·대체 소스로 다시 설계 |
| 인지 시간 부족 | 해당 컷의 대상·근거를 알아보기 전에 교체되어 순간 삽입처럼 보임. 꼭 필요한 장면이어도 발생. 고정 초수·프레임 수만으로 확정 불가 | 같은 샷의 깨끗한 여유 구간 확보, 주변 컷 길이 재배분, 더 잘 읽히는 소스/인서트 구성. 무조건 삭제·슬로모션·중복 재사용 금지 |
| 끝무렵 동작 돌출/미완결 | 설명용으로 유지하던 샷에서 끝 직전 새 동작·팬·줌·표정 변화가 시작되어 주의를 끌지만, 이해 가능한 진행/결과 없이 다음 컷으로 끊김 | 동작 시작 전 안정 구간에서 종료하거나 동작의 이해 가능한 단계까지 유지. 필요한 동작이면 다른 각도로 이어 행동 연속성 확보. 모든 움직임을 제거하거나 양 끝을 같은 이미지로 만들지 않음 |
| 연결 불일치 | 각 샷은 적절해도 연결점에서 대상 위치·크기·시선·운동 방향 또는 시간 진행이 설명과 무관하게 충돌 | 전후 프레이밍·동작 위상·컷 위치 조정, 근거 있는 다른 샷 사용. 같은 인물이라는 이유만으로 연결 승인 금지 |
| 출력 프레임 이상 | 원본은 정상인데 합성/출력에 검정·섬광·중복·누락·잘못된 소스 프레임이 나타남 | fps·속도·리타이밍·레이어·전환·렌더 경로 구분 진단. 원본 트림으로 숨기지 않음 |

의도된 짧은 리액션, 행동 중 매치 컷, 충격을 위한 불연속은 예외가 될 수 있다. 의도와 정상 속도 확인 근거를 남긴다. 두 끝 이미지가 비슷하다는 사실은 중간에 다른 샷이 없거나 동작이 자연스럽다는 증거가 아니다.

## DB → 원본 → 합성 → 연속 시청

1. `source_search`/`source_cut`으로 후보와 사용 이력·분석 상태를 읽는다. DB 구간·인물·설명은 후보 근거이며 정답 보증이 아니다. 이미 분석된 항목은 재사용하고 누락 정보만 분석한다.
2. 대표 이미지는 후보 선별용이다. 선택 범위 전체를 훑고, 모든 의심 전환과 in/out 근처는 `inspect_source_frames`로 **step=1 연속 프레임**을 확인한다. 한 번에 최대 24개이므로 필요한 범위를 이어 조회한다. coarse sampling에서 안 보였다는 이유로 1프레임 혼입 없음 판정 금지.
3. 소스 프레임 번호는 0부터 시작하는 표시 순서다. 타임라인 프레임 번호와 별개다. 23.976/29.97, VFR, 속도·역재생·중첩을 무시한 초×30 계산 금지. VFR은 반환 PTS를 읽고, 실제 배치 후 합성을 다시 확인한다. out은 제외: 마지막 사용 프레임과 첫 제외 프레임을 구분한다.
4. 배치할 때 의미 경계와 실제 음성에 맞춘다. 자막 한 장마다 컷을 강제하지 않는다. 목적 구간·소스 범위·속도·설명 근거·재사용 이유를 기록하고 트랜잭션으로 적용한다. 깨끗한 구간이 짧으면 다른 구성으로 해결하며 혼입 프레임까지 늘리지 않는다.
5. `inspect_timeline_frames`에 명시한 sequence_id와 경계 전후 프레임 번호를 주어 최종 합성을 검수한다. 소스 검사만으로 합성까지 통과 처리하지 않는다. 끝무렵 동작은 마지막 한 장이 아니라 이전의 안정 상태부터 시작·진행을 함께 본다.
6. 동작·리듬·인지 시간은 앞뒤 내레이션과 함께 정상 속도로 재생/출력해 확인한다. 연속 정지 이미지도 정상 속도 시청과 동일하지 않다. 시청 능력이 없는 환경에서는 그 검수는 미완료로 남기고 사용자에게 정확한 구간을 지정한다.
7. 검수 기록: 시퀀스/클립 ID, 소스 경로·프레임/PTS, 타임라인 경계, 분류, 관찰 근거, 수정 전후 in/out, 정상 속도 확인 여부, 남은 불확실성. 수정 뒤 영향받은 양쪽 경계를 재검사한다.

도구의 `mean_rgb_change`는 축소 RGB 평균 절대 차이(0~1)다. 얼굴/샷 식별·광학 흐름·동작 완료 판정이 아니다. 높아도 정상 액션·플래시일 수 있고 낮아도 비슷한 구도의 다른 샷일 수 있다. 자동 합격 점수나 일괄 트림 임계값으로 쓰지 않는다. `complete=false`는 요청 프레임을 전부 얻지 못했다는 뜻이며, `complete=true`도 요청 범위를 얻었다는 뜻일 뿐 품질 합격이 아니다.

# 자막 완료 기준 — 2026-10-31 사용자 수정

쇼츠·롱폼의 내레이션 본 자막에 적용한다. 현재 사용자 지정 문구·분할·연출과 포맷별 스타일은 유지한다. 이 기준은 예전 Phrase 운영 안내와 단순 retime 완료 기준보다 우선한다.

## 1. 초반 및 중간 공백

- 일반적인 처음부터 설명하는 영상은 **첫 자막을 시퀀스 0프레임부터 표시**한다. 첫 음성 검출 시각까지 자막을 비워두는 것을 기본값으로 삼지 않는다. 의도된 무자막 인트로·별도 편집 범위가 명시된 경우에만 그 시작점을 사용하고 예외를 기록한다.
- 먼저 첫 문구가 실제 첫 발화와 일치하고 발화가 누락되지 않았는지 확인한다. 정렬이 잘못되어 첫 자막이 늦게 생긴 경우에는 시작점만 늘려 오류를 숨기지 않는다. 실제 무음 프리롤과 발화 누락을 구분한다. 음성·영상 자체를 임의로 당기지 않는다.
- 연속 내레이션 구간에서는 앞 자막 out = 다음 자막 in. 프레임으로 검사해 의도하지 않은 빈 구간·겹침을 모두 0개로 만든다. 트랙이 여러 개면 실제 표시되는 본 자막 전체를 시각순으로 검사한다.
- 명시한 장면 휴지·무자막 연출은 예외다. 예외 아닌 짧은 호흡은 앞 자막 유지로 연결한다. 긴 침묵까지 무조건 늘려 오래 붙잡아두지 말고 음성 구간·연출을 확인한다.
- 마지막 자막은 실제 마지막 발화와 정한 영상 끝 기준을 따른다. 쇼츠의 내레이션 끝+6프레임 등 기존 사용자 조건을 지킨다. 초반 무공백 조건을 이유로 마지막 자막을 파일 끝까지 무조건 늘리지 않는다.

## 2. 끝의 쉼표·마침표 제거

- 각 자막 표시 문구 끝의 관습적인 **쉼표·마침표(, . ， 。 ．)**와 끝 공백을 제거한다. 분할 후 새로 생긴 각 자막 끝에도 다시 적용한다. 닫는 따옴표·괄호 바로 안에 종결 마침표가 남았는지도 검사한다.
- 문장 중간 쉼표, 소수점·버전·약어·URL·고유명사의 일부인 점은 보존한다. 물음표·느낌표·의도적인 말줄임표는 일괄 삭제하지 않는다. 예: `2.0입니다.` → `2.0입니다`, `어떻게 담았을까요?`는 유지한다. 보호 표기 때문에 남긴 경우 예외로 기록한다.
- 적용 대상은 화면용 자막이다. 원본 대본·TTS 입력·DB 대사·출처의 문장부호를 일괄 제거하지 않는다. 문구를 정리한다는 이유로 발화·어미·의미를 바꾸지 않는다.

## 3. 긴 자막은 retime만으로 해결하지 않음

- 한 장에 짧은 문장 또는 하나의 의미 덩어리를 둔다. 여러 독립 절·문장·열거가 한 자막에 묶여 있으면 실제 발화의 절 경계로 시간상 분할한다. 화면 줄바꿈만 넣고 긴 구간을 해결했다고 하지 않는다.
- 롱폼은 기존 12~24자·1.5~3.5초를 검토 출발점으로 사용한다. **3.5초 초과는 전수 검토 대상**, 5초 초과나 여러 문장이 한 장이면 우선 분할 후보로 다룬다. 이 수치는 강제 절단선이 아니다. 긴 침묵을 포함해 표시시간만 긴 경우도 분리 진단한다. 예외 유지에는 의미·실제 음성·화면 폭상 이유를 기록한다.
- 쇼츠는 기존 짧은 구절·폭·효과 기준을 따른다. 롱폼 수치를 쇼츠에 복사하거나 긴 자막을 짧은 불완전 조각으로 과분할하지 않는다. 고유명사, 수식어와 대상, 목적어와 동사, `해결하지 / 못했던` 같은 보호 구문을 유지한다.
- 사용자 `/` 지정 분할과 확정 경계는 우선한다. 사용자가 이번처럼 긴 자막 개선을 요청한 경우, 기존 분할 보존을 이유로 자동 생성된 과병합을 방치하지 않는다. 시간만 재정렬하라는 요청에서는 임의 재분할하지 말고 문제를 보고한다.
- 실제 음성 위치 정보가 있으면 그 경계로 분할한다. 없으면 먼저 음성 정렬 정보를 확보하거나 실제 음성으로 시각을 확인한다. 글자 수 비례·균등 초수로 타임스탬프를 만들지 않는다.

## 4. 현행 자동 처리와 완료 판정

2026-11-01 구현 기준: Lumina 내부 speech는 모든 모드에서 첫 자막 0프레임, 연속 구간 연결, 끝 쉼표/마침표 정리, 긴 행의 음성 문장·절 경계 분할을 preview 전에 자동 수행한다. 기존 경계는 합치지 않지만 긴 행은 나뉠 수 있다. retime은 원래 트랙·스타일을 보존하고 첫 조각만 원래 ID를 유지한다.

1. 최신 본 자막·내레이션·사용자 확정 문구/분할을 읽고 첫 시작, 공백/겹침, 종결부호, 긴 구간을 기록한다.
2. 내부 speech preview의 caption_quality=gapless-clean-split-v1과 quality_warnings를 확인한다. 표식이 없으면 구버전 결과로 보고 아래 품질 조건을 별도로 보정한다.
3. 전 행을 검수한다. 자동 분할은 보수적인 문장부호·한국어 절 패턴 규칙이며 문맥 이해를 보장하지 않는다. 경계 부족으로 남은 긴 행은 실제 음성 위치로 보정한다. 고유명사 분단·과분할·사용자 확정 경계와 충돌하는지도 확인한다.
4. 일반 영상의 첫 자막 0프레임과 연속 구간 무공백을 확인한다. 명시한 무자막 인트로나 시간만 재정렬하라는 요청은 자동 결과와 충돌할 수 있으므로 그대로 적용하지 않고 개별 편집으로 요청 범위를 지킨다. 현재 없는 예외 옵션을 만들어 호출하지 않는다.
5. 검수한 preview를 적용하고 자막의 새 ID·시간을 다시 읽는다. 재분할에 연결된 TMI도 관련 본 자막 하나에 맞춘다. 기존 폰트·크기·자간·Y좌표·폭을 유지하며 처음·변경 경계·최장 구간·끝부분의 합성과 음성을 확인한다.
6. 저장 후 첫 시작 프레임, 의도하지 않은 공백/겹침 수, 제거 대상 종결부호 잔존 수, 분할 전후 개수, 최장 구간, 롱폼 3.5초/5초 초과 검토·유지 예외, 실제 검수 범위를 보고한다. job done·dirty:false만으로 품질 완료라 하지 않는다.

새 처리기는 새 분석의 preview부터 적용하며 저장된 기존 자막을 실행 즉시 고치지 않는다. Phrase 서버는 필요 없다. 실제 음성을 듣지 못한 검수는 미청취로 남긴다.
