# 자막 완료 기준 — 2026-10-31 사용자 수정

쇼츠·롱폼의 내레이션 본 자막에 적용한다. 현재 사용자 지정 문구·분할·연출과 포맷별 스타일은 유지한다. 이 기준은 예전 Phrase 운영 안내와 단순 retime 완료 기준보다 우선한다.

## 1. 초반 및 중간 공백

- 일반적인 처음부터 설명하는 영상은 **첫 자막을 시퀀스 0프레임부터 표시**한다. 첫 음성 검출 시각까지 자막을 비워두는 것을 기본값으로 삼지 않는다. 의도된 무자막 인트로·별도 편집 범위가 명시된 경우에만 그 시작점을 사용하고 예외를 기록한다.
- 먼저 첫 문구가 실제 첫 발화와 일치하고 발화가 누락되지 않았는지 확인한다. 정렬이 잘못되어 첫 자막이 늦게 생긴 경우에는 시작점만 늘려 오류를 숨기지 않는다. 실제 무음 프리롤과 발화 누락을 구분한다. 음성·영상 자체를 임의로 당기지 않는다.
- 연속 내레이션 구간에서는 앞 자막 out = 다음 자막 in. 프레임으로 검사해 의도하지 않은 빈 구간·겹침을 모두 0개로 만든다. 트랙이 여러 개면 실제 표시되는 본 자막 전체를 시각순으로 검사한다.
- 명시한 장면 휴지·무자막 연출은 예외다. 예외 아닌 짧은 호흡은 앞 자막 유지로 연결한다. 긴 침묵까지 무조건 늘려 오래 붙잡아두지 말고 음성 구간·연출을 확인한다.
- 마지막 자막은 실제 마지막 발화와 정한 영상 끝 기준을 따른다. 쇼츠의 내레이션 끝+6프레임 등 기존 사용자 조건을 지킨다. 초반 무공백 조건을 이유로 마지막 자막을 파일 끝까지 무조건 늘리지 않는다.

## 2. 끝의 쉼표·마침표 제거

- 각 자막 표시 문구 끝의 관습적인 **쉼표·마침표(, . ， 。 ．)**와 끝 공백을 제거한다. 분할 후 새로 생긴 각 자막 끝에도 다시 적용한다. 닫는 따옴표·괄호 바로 안에 종결 마침표가 남았는지도 검사한다.
- 문장 중간 쉼표, 소수점·버전·약어·URL·고유명사의 일부인 점은 보존한다. 물음표·느낌표·의도적인 말줄임표는 일괄 삭제하지 않는다. 예: `2.0입니다.` → `2.0입니다`, `어떻게 담았을까요?`는 유지한다. 보호 표기 때문에 남긴 경우 예외로 기록한다.
- 적용 대상은 화면용 자막이다. 원본 대본·TTS 입력·DB 대사·출처의 문장부호를 일괄 제거하지 않는다. 문구를 정리한다는 이유로 발화·어미·의미를 바꾸지 않는다.

## 3. 긴 자막은 retime만으로 해결하지 않음

- 한 장에 짧은 문장 또는 하나의 의미 덩어리를 둔다. 여러 독립 절·문장·열거가 한 자막에 묶여 있으면 실제 발화의 절 경계로 시간상 분할한다. 화면 줄바꿈만 넣고 긴 구간을 해결했다고 하지 않는다.
- 롱폼은 기존 12~24자·1.5~3.5초를 검토 출발점으로 사용한다. **3.5초 초과는 전수 검토 대상**, 5초 초과나 여러 문장이 한 장이면 우선 분할 후보로 다룬다. 이 수치는 강제 절단선이 아니다. 긴 침묵을 포함해 표시시간만 긴 경우도 분리 진단한다. 예외 유지에는 의미·실제 음성·화면 폭상 이유를 기록한다.
- 쇼츠는 기존 짧은 구절·폭·효과 기준을 따른다. 롱폼 수치를 쇼츠에 복사하거나 긴 자막을 짧은 불완전 조각으로 과분할하지 않는다. 고유명사, 수식어와 대상, 목적어와 동사, `해결하지 / 못했던` 같은 보호 구문을 유지한다.
- 사용자 `/` 지정 분할과 확정 경계는 우선한다. 사용자가 이번처럼 긴 자막 개선을 요청한 경우, 기존 분할 보존을 이유로 자동 생성된 과병합을 방치하지 않는다. 시간만 재정렬하라는 요청에서는 임의 재분할하지 말고 문제를 보고한다.
- 실제 음성 위치 정보가 있으면 그 경계로 분할한다. 없으면 먼저 음성 정렬 정보를 확보하거나 실제 음성으로 시각을 확인한다. 글자 수 비례·균등 초수로 타임스탬프를 만들지 않는다.

## 4. 현행 자동 처리와 완료 판정

2026-11-01 구현 기준: Lumina 내부 speech는 모든 모드에서 첫 자막 0프레임, 연속 구간 연결, 끝 쉼표/마침표 정리, 긴 행의 음성 문장·절 경계 분할을 preview 전에 자동 수행한다. 기존 경계는 합치지 않지만 긴 행은 나뉠 수 있다. retime은 원래 트랙·스타일을 보존하고 첫 조각만 원래 ID를 유지한다.

1. 최신 본 자막·내레이션·사용자 확정 문구/분할을 읽고 첫 시작, 공백/겹침, 종결부호, 긴 구간을 기록한다.
2. 내부 speech preview의 caption_quality=gapless-clean-split-v1과 quality_warnings를 확인한다. 표식이 없으면 구버전 결과로 보고 아래 품질 조건을 별도로 보정한다.
3. 전 행을 검수한다. 자동 분할은 보수적인 문장부호·한국어 절 패턴 규칙이며 문맥 이해를 보장하지 않는다. 경계 부족으로 남은 긴 행은 실제 음성 위치로 보정한다. 고유명사 분단·과분할·사용자 확정 경계와 충돌하는지도 확인한다.
4. 일반 영상의 첫 자막 0프레임과 연속 구간 무공백을 확인한다. 명시한 무자막 인트로나 시간만 재정렬하라는 요청은 자동 결과와 충돌할 수 있으므로 그대로 적용하지 않고 개별 편집으로 요청 범위를 지킨다. 현재 없는 예외 옵션을 만들어 호출하지 않는다.
5. 검수한 preview를 적용하고 자막의 새 ID·시간을 다시 읽는다. 재분할에 연결된 TMI도 관련 본 자막 하나에 맞춘다. 기존 폰트·크기·자간·Y좌표·폭을 유지하며 처음·변경 경계·최장 구간·끝부분의 합성과 음성을 확인한다.
6. 저장 후 첫 시작 프레임, 의도하지 않은 공백/겹침 수, 제거 대상 종결부호 잔존 수, 분할 전후 개수, 최장 구간, 롱폼 3.5초/5초 초과 검토·유지 예외, 실제 검수 범위를 보고한다. job done·dirty:false만으로 품질 완료라 하지 않는다.

새 처리기는 새 분석의 preview부터 적용하며 저장된 기존 자막을 실행 즉시 고치지 않는다. Phrase 서버는 필요 없다. 실제 음성을 듣지 못한 검수는 미청취로 남긴다.
