# Codex / Claude의 Lumina 실행·검수

## 프로젝트와 근거 확인

1. 공통 컷 문법과 대상 포맷 문서를 읽는다. 레퍼런스의 프로젝트 경로·시퀀스명·버전을 기록한다. 호시노는 반드시 `인계 파일/타카나시 호시노.prproj`의 `시퀀스 09`다.
2. 편집은 Lumina MCP로 한다. `get_editor_status`로 연결 상태를 확인하고 `ensure_editor(project_path)`로 GUI와 대상 프로젝트를 준비한 뒤 `list_projects` → `get_project`로 대상 프로젝트·시퀀스를 명시한다. 기본 MCP는 헤드리스 편집을 하지 않는다. 대상이 이미 열려 있으면 미저장 상태를 그대로 사용하며, 다른 프로젝트는 닫지 않는다. 도구의 실제 스키마를 확인한다. `.lumina`를 외부 스크립트로 수정하지 않는다. [MCP 시작·유지와 세 경우](../mcp-lifecycle.md)를 따른다.
3. `.prproj`는 읽기 분석할 수 있다. 가져오기 경고를 반드시 확인한다. 지원되지 않는 MOGRT·Crop·색보정·전환·자막이 있으면 가져온 화면이 원본과 같다고 가정하지 않는다. 이름이 '자막을 입력하세요'인 템플릿도 실제 표시와 다를 수 있다.
4. 검수용 가져오기는 별도 `.lumina`로 저장한다. 이동된 미디어는 실제 파일 경로를 확인한 뒤 MCP로 연결한다. `media.locate`는 확인한 하위 폴더와 명시한 미디어 ID에 한정한다. 길이/미디어 종류 불일치로 거부된 파일을 일괄 `force` 연결하지 않는다. 특히 GIF가 영상에서 정지 이미지로 바뀌면 원본의 움직임 근거로 쓸 수 없다.

## 배치 전에 작성할 컷 계획표

| 구간 / 내레이션 | 대상·주장 | 화면에서 확인할 증거 | 유지/컷/레이어 추가 이유 | 소스와 in/out | 자막·그래픽 | 움직임·소리 | 확인 결과 |
|---|---|---|---|---|---|---|---|
| 시작~끝 | 무엇을 설명하나 | 무엇이 보여야 하나 | 왜 여기서 바꾸나 | 파일·실제 구간 | 읽을 항목 | 필요한 경우만 | 실제 확인/미확인 |

대본을 의미 단위로 묶은 다음 소스를 선택한다. 소스 길이에 맞추려고 의미 단위를 쪼개지 않는다. 자막 분할과 샷 배정은 별도 단계다. 내레이션 편집으로 시간을 이동했다면 원본 SRT 시간을 시퀀스 시간으로 변환해야 한다.

## 실행

- `source_search`로 후보를 좁히고 실제 소스 프레임·구간을 확인한다. DB에 없는 파일은 로컬 검색으로 찾되 근거 없이 유사 장면으로 대체하지 않는다.
- 여러 편집 명령은 `begin_transaction` / `commit_transaction`으로 묶고 실패 시 `rollback_transaction`한다.
- `clip_place`에는 목적 구간을 명시한다. 특히 정지 이미지의 길이를 생략하지 않는다. 덮어쓴 범위를 보고 의도하지 않은 이웃 클립 손상이 있으면 되돌린다.
- 프레이밍·속도·그래픽은 해당 샷에 필요한 것만 적용한다. 롱폼에 쇼츠의 115/130%나 y=1060을 복사하지 않는다.
- 명시한 시퀀스의 `get_timeline_state`로 배치를 다시 읽어 계획표와 비교한다. 프레임 계산은 실제 시퀀스 fps를 쓴다. 호시노 완성본과 다른 세 참고작은 24000/1001fps이며 30fps 고정 계산을 하면 안 된다.

## 검수와 완료

1. `get_frame_image`로 주요 컷, 비교 카드의 각 등장 단계, 자막 최장 구간, 컷 경계 전후를 확인한다.
2. 정지 프레임만으로 동작·리듬·읽기 시간을 판단하지 않는다. 짧은 구간을 재생/내보내기해 실제 속도로 확인한다.
3. 원작 대사·효과음·BGM과 내레이션이 겹치는 구간은 소리로 확인한다. 타임라인의 존재 여부만으로 믹스가 좋다고 보고하지 않는다.
4. 놓친 프레임·검은 틈·갑작스러운 크기 변화·오프라인 미디어·자막 가림·효과 꼬리를 확인한다.
5. `save_project`로 저장한다. 내보내기 요청이 있으면 `export_media` 결과 파일과 검증 상태를 확인한다.
6. 보고에는 완료 구간, 기준 대비 개선한 점, 구하지 못한 소스, 미지원 효과, 실제로 하지 않은 검수를 명시한다.

검수 상태를 `원본 완성 출력 / Lumina 가져오기 합성 / 소스 프레임 / 타임라인`으로 구분한다. 추가로 `정지 프레임 확인 / 연속 재생 확인 / 직접 청취 / 음량 측정`을 별개로 기록한다. 렌더 완료·오디오 스트림 존재·파일 재생 명령 성공은 직접 시청·청취 완료가 아니다. 모델에 오디오 입력이 없으면 청취 미완료로 남긴다.

## 두 에이전트가 이어서 작업할 때

프로젝트/시퀀스 ID, 최신 저장 위치, 수정한 구간, 원복 가능한 트랜잭션, 근거 사례 ID, 사용자 수정, 미확인 항목을 남긴다. 다른 에이전트가 작업 중인 같은 시퀀스를 동시에 변경하지 않는다. 모델명이나 개인 메모리만을 근거로 규칙을 추가하지 않는다.

개선 기록 형식:

```text
사례 ID / 시퀀스 / 시각:
관찰한 원본:
전달상의 문제:
변경안과 이유:
실제 재생·프레임 확인:
사용자 피드백(있을 때만):
공통 규칙으로 승격할지 / 이 영상만의 예외인지:
```


자막 작업은 [자막 완료 기준](caption-quality.md)에 따라 시작점·공백·종결부호·과병합을 전수 검수한다. 음성 정렬 job 성공만으로 완료 처리하지 않는다.
