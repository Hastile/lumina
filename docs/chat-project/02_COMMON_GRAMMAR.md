# 캐디노트 편집 지침 v1.0

2026-10-30 · 쇼츠 / 롱폼 공통 · Codex / Claude 공용

## 1. 최우선 원칙

**난잡하지 않고 직관적으로. 초반에는 볼 이유를 바로 전달하고, 본문에서는 이해와 궁금증이 이어지게 편집한다.**

캐디노트는 창작물의 설계 의도를 해부하는 채널이다. 편집은 시청자가 ‘왜 이렇게 만들었는가’를 화면에서 확인하도록 돕는다. 시청 지속을 위해 먼저 줄일 것은 이해의 마찰이다. 효과·컷·소리를 늘리는 것 자체를 목표로 삼지 않는다.

- 한 순간에 가장 먼저 볼 대상이 분명해야 한다. 비교 화면도 여러 요소가 하나의 비교를 설명하도록 묶는다.
- 내레이션, 자막, 실제 화면이 같은 대상을 가리켜야 한다.
- 새 정보의 등장에는 순서를 준다. 배경 전환·줌·큰 글자·화살표·효과음을 동시에 터뜨리지 않는다.
- 의미가 전달된 강조는 걷어낸다. 설명의 근거가 되는 여백·거리·화면비는 보존한다.
- 정돈된 화면에서도 공개·행동·비교가 진행되면 리듬이 생긴다. 매 순간 움직일 필요는 없다.

사용자의 현재 지시와 확정 취향이 우선한다. 기존 콘텐츠·대본 지침과 함께 사용하며, 쇼츠의 기존 자막 분할·포맷 조건은 유지한다.

## 2. 초반 이탈 방지

첫 화면부터 **무엇을 볼지, 무엇이 이상하거나 궁금한지**를 알아볼 수 있게 한다. 작품을 깊이 아는 사람만 이해할 기술명·설정 용어를 화면 가득 먼저 나열하지 않는다.

1. 제목·썸네일에서 약속한 대상이나 현상을 바로 보여준다. 로고, 인사, 제작 배경이 본론을 늦추지 않게 한다.
2. 질문은 실제로 보이는 차이·행동·모순과 연결한다. 말로만 ‘놀라운 비밀’이라고 예고하지 않는다.
3. 첫 주장에는 짧고 명확한 증거를 붙인다. 답을 전부 공개할 필요는 없지만 볼 가치가 있다는 작은 납득을 초반에 준다.
4. 도입에서 만든 궁금증을 본문의 첫 설명으로 이어간다. 관심을 끈 직후 긴 설정 설명이나 무관한 몽타주로 끊지 않는다.
5. 빠른 도입이어도 화면의 대상과 핵심 문구를 인지할 틈은 준다. 자막·화면·음성이 서로 다른 정보를 경쟁시키지 않게 한다.

첫 화면을 멈춰 ‘무엇에 관한 영상인가’를, 도입을 정상 속도로 재생해 ‘왜 다음을 봐야 하는가’를 확인한다. 고정된 도입 초수나 컷 수를 모든 영상에 강제하지 않는다.

## 3. 본문 시청 지속

- 기본 흐름은 **질문 또는 주장 → 화면 증거 → 해석 → 다음에 확인할 것**이다. 모든 단락을 똑같이 만들라는 뜻은 아니다.
- 궁금증은 적절히 회수한다. 답을 계속 미루거나 같은 예고를 반복해 시간을 늘리지 않는다.
- 이미 이해한 설명·증거는 압축한다. 새 사례는 기존 판단을 보강·반박·확장하는 역할이 있어야 한다.
- 현재 논점을 이해할 만큼 보여준 뒤 다음으로 간다. 행동은 준비→실행→결과, 비교는 기준→차이→의미가 읽혀야 한다.
- 설명 샷, 실제 행동, 비교, 짧은 정리를 필요에 따라 교대한다. 일정 시간마다 무조건 화면이나 BGM을 바꾸지 않는다.
- 챕터 전환은 다음 질문과 연결한다. 타이틀·전환 효과·음악 변화를 매번 모두 사용하지 않는다.
- 결말은 초반 질문에 답하고, 그 답을 뒷받침한 증거를 묶는다. 새 주장만 던진 채 종료하지 않는다.

## 4. 컷·확대·주석의 선택

| 상황 | 선택 | 확인할 점 |
|---|---|---|
| 다음 구절도 같은 행동을 설명함 | 현재 샷 유지 | 자막이 바뀐다는 이유만으로 자르지 않음 |
| 논점·대상·사건이 바뀜 | 새 컷 또는 같은 화면에 새 대상 추가 | 무엇이 바뀌었는지 알아볼 수 있음 |
| 작은 부위가 주장 근거임 | 전체 → 필요하면 위치 표시 → 확대 → 관찰 시간 | 소스만 확대하고 해설 자막은 읽을 크기 유지 |
| 거리·고립·크기 차이·여백이 근거임 | 전체 구도 보존 | 인물 중심 줌으로 공간 관계를 지우지 않음 |
| 두 대상의 차이를 설명함 | 같은 비교 축으로 함께 배치 | 기준선·크기·관찰 부위를 일관되게 맞춤 |
| 추상적인 규칙을 설명함 | 같은 기준 화면에서 변수 하나씩 변경 | 설명용 가공과 실제 원작을 구별 |
| 근거는 충분히 보이지만 화면이 심심함 | 먼저 유지한 상태를 검토 | 장식 추가보다 설명·소스가 적절한지 확인 |

원작의 카메라 이동·작화·강조가 이미 역할을 하면 추가 효과를 생략할 수 있다. 주석은 볼 곳을 안내한 뒤 퇴장시킨다. 밝기를 낮췄다면 역할이 끝난 후 복원한다. 쇼츠에서도 공간 관계가 근거면 무조건 세로 채우기로 자르지 않고 전체 구도 인서트를 검토한다.

## 5. 자막과 그래픽

- 기본 자막은 발화를 따라가고, 큰 그래픽은 핵심 주장·비교·구조를 맡는다. 같은 긴 문장을 양쪽에 중복 표시하지 않는다.
- 얼굴·소품·숫자·관찰 부위를 가리지 않는다. 강조 문구와 자막의 읽는 순서를 분명히 한다.
- 한 장에는 하나의 의미 덩어리를 유지한다. 수식어와 대상, 목적어와 동사, 행동과 결과를 기계적으로 끊지 않는다.
- **롱폼:** Pretendard Medium 60, 자간 -20, 기본 박스 폭 1440px. 호시노 인계 파일의 시퀀스 09에서 확인한 1440×324 박스를 기준으로 한다. 어색한 개행은 좌우 확장 가능. 박스 높이를 허용 줄 수로 해석하지 않는다.
- 실제 폰트 폭과 렌더 결과를 우선한다. 자간 -20을 다른 렌더러의 -20px로 복사하지 않는다. 화면 안 줄바꿈과 시간상 자막 교체를 구분한다.
- **쇼츠:** 기존 자막 분할 기준과 스타일을 유지한다. 롱폼의 널널한 분할을 일괄 적용하지 않는다.
- 타이틀은 등장 뒤 안정된 읽기 구간을 둔다. 긴 표는 항목을 순차 공개하고, 회상용 카드에 새 논거를 숨기지 않는다.

## 6. 소리와 호흡

내레이션을 분명히 들을 수 있어야 한다. 원작 대사가 증거인 순간에는 음성의 주도권을 넘기고 다시 복귀한다. BGM은 분위기와 흐름을 받치며, 효과음은 공개·반응·전환에 필요할 때만 사용한다. 컷마다 같은 타격음이나 휙 소리를 붙이지 않는다. 조용한 구간도 허용한다.

실제 재생으로 첫 음절·끝말 잘림, 원작 대사와 해설의 충돌, 효과음 꼬리, 갑작스러운 음량 차이를 확인한다. 파형이나 타임라인 수치만 보고 청감 검수를 완료했다고 하지 않는다.

## 7. 레퍼런스에서 가져올 원리

- **스토리 / 30일 비밀 채널 실험** (`Czmkes4yAOA`): 판단 기준을 먼저 보여주고 후반의 실제 결과로 회수하기. 정보 카드·수치에서 전체 맥락→볼 곳→읽기 유지 순서 만들기.
- **두공탁 / 연출의 프리렌** (`xfn09HUXSHA`): 컷 틀과 정보량을 화면에서 직접 바꾸며 설명하기. 여백을 먼저 느끼게 하고 개념의 이름 붙이기.
- **두공탁 / 오프닝 건너뛰면 지상렬** (`u_adLgssZu4`): 세부 확대 전 관찰 위치 안내하기. 화면비 경계를 잠깐 짚은 뒤 원래 화면으로 돌아오기.
- **내부 레퍼런스:** 호시노는 인계 파일의 완성 시퀀스 09. 이시고리·덴지·레제와 함께 사례별로 참고하되 오래된 관행이나 효과의 빈도를 목표로 삼지 않는다.

폰트·전환·효과를 그대로 복제하지 않는다. 해당 연출이 해결한 문제를 가져와 우리 영상에 맞춘다. 원작 자체의 연출과 유튜버가 추가한 편집은 구별한다. 외부 영상 화면은 표본 검수했으며 직접 청취가 미완료이므로, 음향 규칙은 청취로 입증한 레퍼런스 성향이 아닌 실행 지침이다.

## 8. Codex / Claude 실행·검수

편집 전 각 구간에 `주장 / 화면 증거 / 먼저 볼 대상 / 추가 연출 / 보호할 요소 / 다음으로 넘어갈 조건`을 적는다. 정해진 효과 프리셋보다 이 판단을 우선한다.

Lumina 프로젝트의 실제 편집은 MCP를 사용한다. `.lumina`를 별도 스크립트로 고치지 않는다. 소스·프레임 경계·최종 합성 화면·소리를 확인한다. 쇼츠 작업은 저장소의 `docs/shorts-editing/README.md`와 연결된 문법을 먼저 읽는다.

완료 전 확인:

- 첫 화면에서 대상이 보이고, 도입에서 볼 이유가 생기는가?
- 말하는 대상과 실제 화면이 맞으며, 주장을 확인할 증거가 있는가?
- 무엇을 먼저 봐야 할지 즉시 알 수 있는가?
- 정상 속도에서 읽고 이해할 시간이 있는가?
- 확대·자막·표시가 증거를 가리지 않는가?
- 효과를 빼도 같거나 더 잘 전달되는 부분을 덜었는가?
- 초반의 약속을 회수하고, 다음 구간으로 갈 이유가 이어지는가?
- 실제 화면·소리를 확인한 범위와 미확인 범위를 구별했는가?

초반 이탈 방지와 시청 지속은 **목표**다. 이 지침만으로 성과 개선이 입증된 것은 아니다. 업로드 후 구간별 시청 지속 데이터를 확보하면 이탈 지점의 실제 장면을 다시 검토하고, 소재·유입·길이 차이를 고려해 개선한다.

# 공통 컷 문법 — 쇼츠 / 롱폼

## 기본 단위는 자막 한 장이 아니라 시청자가 이해해야 하는 한 가지

샷을 배정하기 전에 내레이션을 **설명 대상 + 주장/행동 + 필요한 증거**로 묶는다. 한 문장에 대상이 두 개면 나눌 수 있고, 여러 자막이 같은 행동을 설명하면 한 샷을 유지할 수 있다. 자막 교체·문장 마침표·음악 박자는 자동 컷 명령이 아니다.

| 질문 | 기본 선택 | 예외 / 주의 |
|---|---|---|
| 보여줄 대상·사건·논점이 바뀌는가? | 새 컷 또는 같은 화면 안 대상 추가 | 비교가 목적이면 이전 대상을 남기는 편이 낫다 |
| 현재 샷이 다음 구절도 충분히 설명하는가? | 유지 | 대상이 가려지거나 읽을 증거가 작으면 리프레임 |
| 동작이 준비→실행→결과로 이어지는가? | 결과를 인지할 때까지 유지 | 의도적인 시점 전환으로 행동을 더 분명히 보여줄 수 있을 때만 컷 |
| 말은 끝났지만 시청자가 자료를 읽는 중인가? | 읽을 시간을 확보 | 설명과 별개인 자료를 길게 붙잡지 않는다 |
| 같은 대상을 더 자세히 보아야 하는가? | 부분 확대·강조 또는 설명용 인서트 | 의미 없는 전후 줌 반복 금지 |
| 화면을 바꿀 이유가 단지 시간이 지났기 때문인가? | 유지하거나 더 적합한 소스를 찾음 | 반복 동작·정지 화면의 지루함도 실제로 확인해야 한다 |

**새 컷·레이어 등장·텍스트 강조·카메라 이동은 서로 다른 수단이다.** 같은 논점에서 키워드가 추가된다고 전체 화면을 갈아엎지 않는다. 이시고리의 세 가지 정체성 누적, 레제의 STP 누적은 이 원칙의 근거다.

비교 정보를 유지한다는 것이 배경 영상까지 고정하라는 뜻은 아니다. 이시고리 183.8초와 185.5초의 Lumina 합성 표본에서는 첫 문구가 남은 채 행동 영상이 바뀌고 두 번째 문구가 추가된다. **기억할 정보는 유지하고, 현재 주장을 입증하는 영상은 갱신**할 수 있다. 배경 컷과 새 항목 등장으로 시선이 동시에 분산되면 둘의 시점을 어긋나게 하거나 배경의 대비를 낮춘다. 이 조정은 개선안이며 원본의 청감·리듬 검증 결과가 아니다.

## 의미 경계와 공개 시점

- 수식어와 대상, 목적어와 동사, 행동과 결과를 무의미하게 분리하지 않는다. `들고 / 온`, `해결하지 / 못했던`은 자막에서도 컷 계획에서도 경고 신호다.
- 새 주어가 나오면 그 주어를 보여준다. 비교에서는 이전 주어와 새 주어를 함께 놓는 방법도 검토한다.
- 원인→결과, 질문→답, 기대→반전의 공개 시점을 지킨다. 정답을 숨긴 도입에서 얼굴·이름·결과 화면을 미리 노출하지 않는다.
- 특정 사건을 말할 때는 그 사건의 실제 소스를 쓴다. 같은 인물의 다른 전투를 해당 사건처럼 제시하지 않는다. 비유·모티브 비교는 오해하지 않도록 이름·출처·연결 설명을 붙인다.
- 도입에서 짧은 컷을 쓰더라도 하나의 궁금증을 만들어야 한다. 빠른 컷의 개수가 흥미를 보장하지 않는다.

## 소스 선택 순서

1. 주장에 직접 대응하는 행동·표정·디자인·문서 증거.
2. 해당 대상을 정확히 보여주는 중립 샷이나 정지 이미지.
3. 설명을 돕는 비교 자료·도식. 비유인지 사실의 증거인지 구분.
4. 장식용 영상은 맥락을 해치지 않는 보조로만 사용.

소스 DB 설명·파일명은 후보를 찾는 단서다. 실제 프레임과 구간을 확인한다. 화면에 글자가 이미 많거나 얼굴이 잘리는 소스를 억지로 쓰지 않는다. 좋은 원본 동작을 먼저 선택하고 정지 샷에 일괄 줌을 붙여 활기를 흉내 내지 않는다.

## 중복 장면 재활용은 매우 신중하게

**사용자 확정 지침 (2026-10-31): 중복 장면은 정말 신중하게 재활용한다. 초안에서 같은 장면으로 빈 구간을 때운 듯한 편집이 많이 보였다는 피드백이다.** 쇼츠·롱폼 모두 적용하며 초안도 예외가 아니다.

- 이미 사용한 장면을 편한 기본 소스로 반복 배치하지 않는다. 같은 인물이 나온다는 이유나 길이가 맞는다는 이유만으로 재사용하지 않는다.
- 재사용할 때는 **앞선 사용 위치·당시 역할·이번에 새로 보여줄 근거·다른 소스보다 이 장면이 필요한 이유**를 컷 계획에 적는다. 이유를 구체적으로 설명할 수 없으면 다른 소스를 찾거나 구성을 바꾼다.
- 회상·전후 비교·복선 회수·같은 사건의 다른 세부를 검증하는 경우처럼, 다시 보여주는 행위 자체가 설명에 기여할 때만 검토한다. '강조용', '분위기용', '소스 부족'이라는 이름만 붙여 반복을 정당화하지 않는다.
- 크롭·줌·좌우 반전·속도 변경·몇 프레임의 in/out 변경만으로 같은 장면이 새 근거가 되지는 않는다. 같은 파일의 다른 구간도 실질적으로 같은 행동·구도면 중복 후보로 본다. 반대로 같은 파일 안의 별개 사건을 파일명만으로 중복 판정하지 않는다.
- 소스가 부족하면 다른 실제 장면·정지 이미지·비교 자료·도식을 검토하거나, 설명에 맞는 샷을 자연스럽게 유지한다. 적합한 자료를 못 찾은 구간은 미해결로 남긴다. 관련 없는 영상이나 반복 샷으로 채워 완료 처리하지 않는다.
- 검수 때는 반복 사용한 소스 구간을 모아 최초 사용과 재사용을 앞뒤 내레이션까지 연속해서 비교한다. 새 정보가 있는지, 장면이 다시 시작되는 느낌이나 때운 느낌이 나는지 확인하고 불필요한 반복을 교체한다. 반복 횟수·간격에 기계적인 허용 기준을 두지 않는다.

## 길이와 속도

- 고정 초수나 '자막 N개당 1컷'을 목표로 삼지 않는다. 네 레퍼런스의 미디어 클립 중앙값은 2.77~4.00초지만, 겹친 이미지·오버레이가 포함된 **클립 인스턴스** 통계라 샷 길이 규칙으로 사용할 수 없다.
- 짧은 컷이 연달아 나오면 각각 새 정보가 있는지 확인한다. 이름 카드·누적 등장·의도적인 리액션은 설명 샷과 다르게 평가한다.
- 긴 컷은 하나의 행동·비교·자료 읽기가 이어지면 허용한다. 길이만으로 부족한 리듬이라고 판정하지 않는다.
- 속도는 100%부터 검토한다. 부족한 길이는 소스 범위·샷 설계를 먼저 바꾼다. 속도 조절은 동작이 자연스럽고 목적이 있을 때만 사용한다. 원본에 잦은 속도 변경이 있어도 그 빈도를 목표로 삼지 않는다.
- 쇼츠의 기존 최소 길이·마커 관련 사용자 조건은 쇼츠에서 유지한다. 롱폼에 숫자만 복사하지 않는다.

## 화면 구성과 움직임

- 얼굴/설명 부위/읽을 문구가 자막과 겹치지 않게 배치한다. 크기는 채우기보다 알아보기 쉬운 정도로 정한다.
- 비교는 같은 축으로 정렬한다. 키 비교는 발 기준선과 표시 수치를, 디자인 비교는 해당 부위와 비슷한 확대율을 사용한다. 그림 포즈만으로 실제 신체 비율을 확정하지 않는다.
- 기본 프레이밍은 고정한다. 카메라 이동에는 추적·공개·관찰 부위 안내 중 하나의 목적이 있어야 한다. 대상이 멈추면 추적도 멈춘다.
- 두 인물을 비교할 때마다 컷을 왕복하기보다 한 화면에 남겨 비교 비용을 줄인다. 정보가 과밀하면 비교 항목을 나눠 순차 제시한다.
- 비교 축에 맞는 크기를 쓴다. 신장 비교에는 발 기준선이 필요하지만 헤어스타일 비교에는 머리의 크기·각도가 우선이다. 전신 키를 맞추는 규칙을 모든 비교에 적용하지 않는다. 이시고리 201초 표본의 전신 3인 구성은 인물 소개에 유리하나 머리 형태 비교를 개선하려면 헤어 인서트가 더 직접적이다.
- 이미 소스 안에 화살표·빛·동작 강조가 있으면 새 강조를 자동으로 겹치지 않는다. 호시노 101초 표본에는 약실 부근의 노란 원형 강조가 보인다. 먼저 기존 강조의 역할을 확인하고, 자막이 그 부위를 가리면 자막 위치부터 검토한다.

## 증거를 보이게 하는 연출과 보존할 구도

두공탁 두 편의 화면 근거（로컬 참조: `D:/Dev/lumina/docs/editing-grammar/references/dugong-frieren-opening.md`）를 바탕으로 다음을 공통 적용 후보로 삼는다.

- 작은 세부가 근거라면 **전체 맥락→관찰 위치 지정→확대→읽기 유지** 순서를 검토한다. 확대되는 소스와 해설 자막은 분리한다.
- 여백·인물 사이 거리·화면비가 근거라면 전체 구도를 보호한다. 자동 채우기 크롭과 인물 중심 줌으로 증거를 없애지 않는다. 쇼츠에서도 전체 구도 인서트를 선택할 수 있다.
- 주석은 필요한 순간에만 보이고 퇴장시킨다. 가이드로 시선을 잡은 후 원래 밝기와 깨끗한 화면을 회복한다. 원작에 이미 충분한 안내가 있으면 추가 강조를 생략한다.
- 설명용 합성·변형은 원작과 구분한다. 기준 화면에서 변수를 하나씩 바꾸고, 원본을 다시 제시한다. 가공 결과를 원작의 사실로 오해하게 하지 않는다.
- 애니 원작의 카메라 이동·작화와 채널 편집의 개입을 구별한다. 좋은 소스 구간을 온전히 고르는 것도 편집이다.

## 읽을 정보와 스쳐 보여줄 정보

카드마다 `역할 = 읽기 / 회상 / 분위기`를 먼저 정한다. 읽기 카드는 처음 보는 내용을 정상 속도에서 이해할 수 있어야 한다. 회상 카드는 이미 설명한 항목을 다시 불러오는 용도이며, 짧아도 되는 대신 새 논거를 숨겨 넣지 않는다. 분위기 카드는 문장 전체를 읽어야 다음 내용을 이해하는 구조로 쓰지 않는다.

덴지 258.5/259.5/260.5초의 Lumina 표본은 큰 SWOT 약어와 네 개의 문장을 가진 카드다. 정지 화면에서 글자가 선명하다는 사실은 약 1초에 네 문장을 읽을 수 있다는 뜻이 아니다. 반대로 짧다는 이유만으로 실패한 컷이라고 확정하지도 않는다. 앞뒤 음성과 역할을 확인한 뒤, 읽기 목적이면 핵심 차이 하나를 남기고 회상 목적이면 이미 설명한 핵심어로 압축한다. **카드의 모든 줄을 읽히려고 영상 전체를 무작정 늘리는 것은 기본 해결책이 아니다.**

## 경계 품질

컷·프레임 튐 판정과 보정（로컬 참조: `D:/Dev/lumina/docs/editing-grammar/cut-quality.md`）을 적용한다. 대표 이미지나 장면 변화 수치만으로 합격시키지 않는다.

- 원본의 이전/다음 장면이 한두 프레임 섞이지 않게 in/out을 검사한다. 소스 내부 장면 전환도 확인한다.
- 컷 직전/직후, 강조 등장 직후를 프레임 단위로 본다. 흰 플래시·디졸브 잔상·점프를 길이 늘리기나 느린 재생으로 숨기지 않는다.
- 기본은 명확한 컷이다. 전환 효과는 시간·공간·챕터 관계를 설명할 때 사용한다. 특정 Premiere 플러그인의 전환을 재현하는 것 자체가 목표가 아니다.

## 개선안 평가

레퍼런스를 바꿀 때 `기존 방식 → 문제 → 대안 → 검수 결과`를 남긴다. 좋은 변화는 (1) 말하는 대상이 더 빨리 보이고, (2) 비교·자료가 더 쉽게 읽히며, (3) 불필요한 전환이 줄고, (4) 행동과 감정의 흐름이 보존되는 것이다. 컷 수·줌 수·효과음 수 증가를 발전의 지표로 삼지 않는다.

# 컷·프레임 튐의 판정과 보정

2026-10-31 사용자 요청을 기준으로 정의한 작업 용어다. 모든 업계 용례를 하나로 제한하는 표준 정의는 아니다.

**컷이 튄다**: 의도한 정보·동작·시선·리듬의 연결보다 화면 변화 자체가 먼저 인지되어 설명을 방해하는 편집 결과. 정상적인 하드 컷이나 큰 화면 변화 자체는 결함이 아니다.
**프레임이 튄다**: 프레임 단위에서 의도하지 않은 영상·위치·밝기·시간 진행의 불연속이 나타나는 현상. 다른 샷 혼입, 검은/흰 프레임, 잘못된 소스 매핑과 렌더 문제가 원인일 수 있다. 정상적인 애니메이션 홀드·반복 프레임을 드롭으로 단정하지 않는다.

## 원인별 판정

| 분류 | 엄밀한 판정 근거 | 보정 |
|---|---|---|
| 다른 샷 혼입 | 선택한 소스 구간의 처음/끝 또는 내부에 의도하지 않은 다른 샷이 표시 프레임 1개 이상 존재. DB 대표 이미지가 같아도 제외 불가 | 실제 전환 프레임을 찾고 out을 다른 샷의 첫 프레임 직전까지로 제한. [in,out)에서 out은 제외되므로 다른 샷 첫 프레임을 out으로 설정. 앞쪽 혼입은 in 이동. 필요한 타임라인 길이는 인접 샷·대체 소스로 다시 설계 |
| 인지 시간 부족 | 해당 컷의 대상·근거를 알아보기 전에 교체되어 순간 삽입처럼 보임. 꼭 필요한 장면이어도 발생. 고정 초수·프레임 수만으로 확정 불가 | 같은 샷의 깨끗한 여유 구간 확보, 주변 컷 길이 재배분, 더 잘 읽히는 소스/인서트 구성. 무조건 삭제·슬로모션·중복 재사용 금지 |
| 끝무렵 동작 돌출/미완결 | 설명용으로 유지하던 샷에서 끝 직전 새 동작·팬·줌·표정 변화가 시작되어 주의를 끌지만, 이해 가능한 진행/결과 없이 다음 컷으로 끊김 | 동작 시작 전 안정 구간에서 종료하거나 동작의 이해 가능한 단계까지 유지. 필요한 동작이면 다른 각도로 이어 행동 연속성 확보. 모든 움직임을 제거하거나 양 끝을 같은 이미지로 만들지 않음 |
| 연결 불일치 | 각 샷은 적절해도 연결점에서 대상 위치·크기·시선·운동 방향 또는 시간 진행이 설명과 무관하게 충돌 | 전후 프레이밍·동작 위상·컷 위치 조정, 근거 있는 다른 샷 사용. 같은 인물이라는 이유만으로 연결 승인 금지 |
| 출력 프레임 이상 | 원본은 정상인데 합성/출력에 검정·섬광·중복·누락·잘못된 소스 프레임이 나타남 | fps·속도·리타이밍·레이어·전환·렌더 경로 구분 진단. 원본 트림으로 숨기지 않음 |

의도된 짧은 리액션, 행동 중 매치 컷, 충격을 위한 불연속은 예외가 될 수 있다. 의도와 정상 속도 확인 근거를 남긴다. 두 끝 이미지가 비슷하다는 사실은 중간에 다른 샷이 없거나 동작이 자연스럽다는 증거가 아니다.

## DB → 원본 → 합성 → 연속 시청

1. `source_search`/`source_cut`으로 후보와 사용 이력·분석 상태를 읽는다. DB 구간·인물·설명은 후보 근거이며 정답 보증이 아니다. 이미 분석된 항목은 재사용하고 누락 정보만 분석한다.
2. 대표 이미지는 후보 선별용이다. 선택 범위 전체를 훑고, 모든 의심 전환과 in/out 근처는 `inspect_source_frames`로 **step=1 연속 프레임**을 확인한다. 한 번에 최대 24개이므로 필요한 범위를 이어 조회한다. coarse sampling에서 안 보였다는 이유로 1프레임 혼입 없음 판정 금지.
3. 소스 프레임 번호는 0부터 시작하는 표시 순서다. 타임라인 프레임 번호와 별개다. 23.976/29.97, VFR, 속도·역재생·중첩을 무시한 초×30 계산 금지. VFR은 반환 PTS를 읽고, 실제 배치 후 합성을 다시 확인한다. out은 제외: 마지막 사용 프레임과 첫 제외 프레임을 구분한다.
4. 배치할 때 의미 경계와 실제 음성에 맞춘다. 자막 한 장마다 컷을 강제하지 않는다. 목적 구간·소스 범위·속도·설명 근거·재사용 이유를 기록하고 트랜잭션으로 적용한다. 깨끗한 구간이 짧으면 다른 구성으로 해결하며 혼입 프레임까지 늘리지 않는다.
5. `inspect_timeline_frames`에 명시한 sequence_id와 경계 전후 프레임 번호를 주어 최종 합성을 검수한다. 소스 검사만으로 합성까지 통과 처리하지 않는다. 끝무렵 동작은 마지막 한 장이 아니라 이전의 안정 상태부터 시작·진행을 함께 본다.
6. 동작·리듬·인지 시간은 앞뒤 내레이션과 함께 정상 속도로 재생/출력해 확인한다. 연속 정지 이미지도 정상 속도 시청과 동일하지 않다. 시청 능력이 없는 환경에서는 그 검수는 미완료로 남기고 사용자에게 정확한 구간을 지정한다.
7. 검수 기록: 시퀀스/클립 ID, 소스 경로·프레임/PTS, 타임라인 경계, 분류, 관찰 근거, 수정 전후 in/out, 정상 속도 확인 여부, 남은 불확실성. 수정 뒤 영향받은 양쪽 경계를 재검사한다.

도구의 `mean_rgb_change`는 축소 RGB 평균 절대 차이(0~1)다. 얼굴/샷 식별·광학 흐름·동작 완료 판정이 아니다. 높아도 정상 액션·플래시일 수 있고 낮아도 비슷한 구도의 다른 샷일 수 있다. 자동 합격 점수나 일괄 트림 임계값으로 쓰지 않는다. `complete=false`는 요청 프레임을 전부 얻지 못했다는 뜻이며, `complete=true`도 요청 범위를 얻었다는 뜻일 뿐 품질 합격이 아니다.

# 자막 완료 기준 — 2026-10-31 사용자 수정

쇼츠·롱폼의 내레이션 본 자막에 적용한다. 현재 사용자 지정 문구·분할·연출과 포맷별 스타일은 유지한다. 이 기준은 예전 Phrase 운영 안내와 단순 retime 완료 기준보다 우선한다.

## 1. 초반 및 중간 공백

- 일반적인 처음부터 설명하는 영상은 **첫 자막을 시퀀스 0프레임부터 표시**한다. 첫 음성 검출 시각까지 자막을 비워두는 것을 기본값으로 삼지 않는다. 의도된 무자막 인트로·별도 편집 범위가 명시된 경우에만 그 시작점을 사용하고 예외를 기록한다.
- 먼저 첫 문구가 실제 첫 발화와 일치하고 발화가 누락되지 않았는지 확인한다. 정렬이 잘못되어 첫 자막이 늦게 생긴 경우에는 시작점만 늘려 오류를 숨기지 않는다. 실제 무음 프리롤과 발화 누락을 구분한다. 음성·영상 자체를 임의로 당기지 않는다.
- 연속 내레이션 구간에서는 앞 자막 out = 다음 자막 in. 프레임으로 검사해 의도하지 않은 빈 구간·겹침을 모두 0개로 만든다. 트랙이 여러 개면 실제 표시되는 본 자막 전체를 시각순으로 검사한다.
- 명시한 장면 휴지·무자막 연출은 예외다. 예외 아닌 짧은 호흡은 앞 자막 유지로 연결한다. 긴 침묵까지 무조건 늘려 오래 붙잡아두지 말고 음성 구간·연출을 확인한다.
- 마지막 자막은 실제 마지막 발화와 정한 영상 끝 기준을 따른다. 쇼츠의 내레이션 끝+6프레임 등 기존 사용자 조건을 지킨다. 초반 무공백 조건을 이유로 마지막 자막을 파일 끝까지 무조건 늘리지 않는다.

## 2. 끝의 쉼표·마침표 제거

- 각 자막 표시 문구 끝의 관습적인 **쉼표·마침표(, . ， 。 ．)**와 끝 공백을 제거한다. 분할 후 새로 생긴 각 자막 끝에도 다시 적용한다. 닫는 따옴표·괄호 바로 안에 종결 마침표가 남았는지도 검사한다.
- 문장 중간 쉼표, 소수점·버전·약어·URL·고유명사의 일부인 점은 보존한다. 물음표·느낌표·의도적인 말줄임표는 일괄 삭제하지 않는다. 예: `2.0입니다.` → `2.0입니다`, `어떻게 담았을까요?`는 유지한다. 보호 표기 때문에 남긴 경우 예외로 기록한다.
- 적용 대상은 화면용 자막이다. 원본 대본·TTS 입력·DB 대사·출처의 문장부호를 일괄 제거하지 않는다. 문구를 정리한다는 이유로 발화·어미·의미를 바꾸지 않는다.

## 3. 긴 자막은 retime만으로 해결하지 않음

- 한 장에 짧은 문장 또는 하나의 의미 덩어리를 둔다. 여러 독립 절·문장·열거가 한 자막에 묶여 있으면 실제 발화의 절 경계로 시간상 분할한다. 화면 줄바꿈만 넣고 긴 구간을 해결했다고 하지 않는다.
- 롱폼은 기존 12~24자·1.5~3.5초를 검토 출발점으로 사용한다. **3.5초 초과는 전수 검토 대상**, 5초 초과나 여러 문장이 한 장이면 우선 분할 후보로 다룬다. 이 수치는 강제 절단선이 아니다. 긴 침묵을 포함해 표시시간만 긴 경우도 분리 진단한다. 예외 유지에는 의미·실제 음성·화면 폭상 이유를 기록한다.
- 쇼츠는 기존 짧은 구절·폭·효과 기준을 따른다. 롱폼 수치를 쇼츠에 복사하거나 긴 자막을 짧은 불완전 조각으로 과분할하지 않는다. 고유명사, 수식어와 대상, 목적어와 동사, `해결하지 / 못했던` 같은 보호 구문을 유지한다.
- 사용자 `/` 지정 분할과 확정 경계는 우선한다. 사용자가 이번처럼 긴 자막 개선을 요청한 경우, 기존 분할 보존을 이유로 자동 생성된 과병합을 방치하지 않는다. 시간만 재정렬하라는 요청에서는 임의 재분할하지 말고 문제를 보고한다.
- 실제 음성 위치 정보가 있으면 그 경계로 분할한다. 없으면 먼저 음성 정렬 정보를 확보하거나 실제 음성으로 시각을 확인한다. 글자 수 비례·균등 초수로 타임스탬프를 만들지 않는다.

## 4. 실행 순서와 완료 판정

1. 최신 본 자막의 트랙·ID·문구·in/out·스타일과 실제 내레이션을 읽고 첫 시작 프레임, 공백/겹침, 끝 문장부호, 긴 구간 목록을 만든다. 과거 SRT·Phrase 데이터로 덮지 않는다.
2. 문구 끝 정리와 의미 분할 계획을 세운다. `retime`은 현행 문구·분할을 보존하는 시간 정렬이며 문장부호 제거·긴 자막 재분할 도구가 아니다. 기존 정렬이 없으면 내부 speech 도구로 먼저 경계 근거를 확보한다.
3. 실제 정의를 조회한 `caption_set`·`caption_split_text` 등으로 정리·분할한다. 분할 시 문구와 클립을 함께 나누고 ID 변경을 다시 읽는다. 새 자막 트랙을 중복 생성하지 않는다.
4. 필요하면 최신 분할 결과로 `speech_start(mode="retime")` → `speech_job` 전 행 검수 → `speech_apply`. `script`도 입력 줄 보존이므로 대본 한 문단을 넣으면 자동으로 적절히 잘라줄 것이라 기대하지 않는다.
5. 정렬 적용 후 첫 자막 0프레임, 연결 경계, 최종 발화 끝, 분할 후 문장부호를 다시 검사한다. 엔진이 첫 발화 시각을 유지했다면 이 정책에 맞는 첫 시작점을 별도 편집 도구로 보정한다. 지원되지 않는 파라미터를 만들어 호출하지 않는다.
6. 합성으로 첫 화면·각 변경 경계·가장 긴 자막·끝부분을 검사하고, 실제 음성으로 교체 타이밍과 읽는 호흡을 확인한다. 글자 수뿐 아니라 기존 폰트·크기·자간·박스 폭으로 확인한다. 기존 Y좌표·스타일을 임의 초기화하지 않는다.
7. 저장 후 보고: 첫 시작 프레임, 의도하지 않은 공백/겹침 수, 제거 대상 종결부호 잔존 수, 분할 전후 개수, 최장 구간, 3.5초/5초 초과 검토 및 예외(롱폼), 음성/합성 검수 범위. `job done`·`dirty:false`만으로 품질 완료라 하지 않는다.

현재 내부 음성 정렬이 Phrase 서버 없이 동작한다는 사실과 자막 품질이 같다는 주장은 별개다. 이 문서는 요구 품질·후처리 절차이며 모든 정책이 엔진에 자동 구현됐다는 뜻이 아니다. 기능 부재·음성 미검수는 명시한다.
