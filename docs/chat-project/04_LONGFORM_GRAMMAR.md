# 롱폼 편집 문법

공통 컷 판단은 common-cuts.md（로컬 참조: `D:/Dev/lumina/docs/editing-grammar/common-cuts.md`）를 따른다. 이 문서는 긴 설명에서 기억·정보량·호흡을 관리하는 방법을 추가한다.

## 1. 구조: 장식보다 논점의 진행

작품마다 같은 목차를 강제하지 않는다. 네 참고작에서 관찰한 외형/모티브/서사/비교/분석의 이동을 활용하되, 대본의 질문을 가장 잘 풀어주는 순서를 고른다.

- 도입: 이번에 알아볼 질문과 시각적 특징을 빠르게 연결한다. 레제의 원작 대사 도입처럼 목소리·사건 자체가 질문을 만드는 방식도 허용한다.
- 설명: `주장 → 화면 증거 → 해석`이 연결되도록 한다. 출처 화면을 보여줬다는 사실만으로 주장의 근거가 충분해지는 것은 아니다.
- 전환: 논점이 바뀌면 시청자가 위치를 이해하도록 화면·짧은 타이틀·음악 중 필요한 수단을 선택한다. 매 챕터마다 모두 동원하지 않는다.
- 결론: 앞선 증거를 묶어 도입 질문에 답한다. 이미 본 장면을 재사용할 때는 새 요약·비교의 역할이 있어야 한다.

## 2. 설명 유형별 화면 선택

| 설명 유형 | 권장 화면 | 피할 것 |
|---|---|---|
| 외형·색·소품 | 전체 실루엣 → 해당 부위/물건, 필요하면 색칩·짧은 표시 | 인물 얼굴만 반복하면서 소품 설명 |
| 크기·차이 비교 | 동시 배치, 기준선/동일 확대율, 라벨 | 크기가 다른 원본을 그대로 놓고 우열을 암시 |
| 명칭·어원·모티브 | 용어 → 실제 대상 → 연결점 | 이름이 비슷하다는 이유만으로 유래를 확정 |
| 서사 사건 | 실제 사건의 준비·행동·결과 | 다른 사건을 그 사건처럼 보이게 붙임 |
| 추상 분석 | 구체적인 사례 뒤 핵심어를 누적 | 분석 용어를 큰 글자로만 반복 |
| 숫자·매출·인용 | 해당 수치/문장 확대 + 출처 유지 | 기사 전체 축소 화면으로 검증을 대신함 |
| 유머·반응 | 맥락을 해치지 않는 짧은 반응과 복귀 | 다음 설명을 덮는 밈·효과음 |

호시노의 산탄총 설명은 실제 장전 부위를 보여주는 방식, 이시고리의 디저트 모티브는 실제 디저트 이미지, 덴지의 전기톱 색은 실제 제품 비교를 활용한다. 이를 발전시키려면 설명 부위와 비교 축을 더욱 분명히 하고 불필요한 검색 화면·부연을 줄인다.

## 3. 자막과 그래픽의 역할 분리

- 기본 자막: **Pretendard Medium 60, 자간 -20**. 호시노 완성본 `시퀀스 09`에서 실제 박스 **1440×324**를 확인했다. 기본 폭 1440은 근거가 있으며 애매한 개행은 사용자 허용대로 좌우 확장 가능하다. 확장 상한은 아직 미정이다.
- 자막 위치는 렌더 결과와 화면 내용을 보고 정한다. Premiere 추출의 로컬 좌표를 Lumina 최종 화면 좌표로 그대로 복사하지 않는다.
- 글자 수가 아닌 실제 폰트 폭을 우선한다. 30자/5초는 재검토 신호이지 탈락 조건이 아니다. 현재 Phrase Studio v1은 폭 측정을 하지 않으며 호시노 감사에서 종결·결합 표현 오류가 확인됐으므로 결과를 자동 확정하지 않는다.
- 박스 내부 개행과 시간상 자막 교체를 구분한다. 붙어야 할 표현을 분리하거나 무조건 폰트를 줄여 해결하지 않는다. 기본 허용 줄 수는 아직 확정하지 않았다.
- 이름표는 누가 누구인지, 강조어는 무엇을 볼지, 보조 설명은 내레이션에서 생략한 짧은 정보를 맡는다. 세 층이 같은 문장을 중복해 보여주지 않게 한다.
- 호시노 완성본에는 Black 120/200 등도 보이지만 기본값으로 복제하지 않는다. 큰 강조는 짧은 공개·반전처럼 목적이 있는 경우만 사용한다. 쇼츠의 pop/slam/fade 비율을 롱폼에 강제하지 않는다.

## 4. 누적 설명과 비교 카드

이시고리 183.39~188.65초는 세 설명을 차례로 쌓고, 레제 457.25~465.30초는 STP의 대상을 순차 추가한다. **이미 이해한 항목을 화면에 남기고 새 항목만 추가**하는 방법은 긴 설명의 기억 부담을 낮출 수 있다.

개선 원칙:

1. 등장 순서는 말하는 순서와 맞춘다. 끝에 한꺼번에 뜨는 결과표보다 진행을 따라갈 수 있어야 한다.
2. 현재 설명하는 항목만 대비를 높이고 이전 항목은 남겨 비교할 수 있게 한다.
3. 마지막 상태에 읽고 비교할 시간이 필요하다. 해당 주장이 끝나기 전에 표를 치우지 않는다.
4. 글이 많으면 먼저 읽기 카드인지 회상 몽타주인지 구분한다. 덴지의 258.17~261.18초 SWOT 세 카드는 각각 약 1초에 여러 항목을 담으며, Lumina 합성 표본에서도 네 문장과 큰 약어가 확인됐다. 모든 항목의 읽기가 목적이면 핵심 축 하나를 충분히 읽히거나 설명 구간으로 분산한다. 회상 목적이면 이미 설명한 핵심어로 압축한다. 앞뒤 음성 미청취 상태에서는 원본의 의도를 확정하지 않는다.
5. 표를 만든다고 사건 영상까지 줄일 필요는 없다. 정적 비교 화면과 실제 행동 화면의 역할을 번갈아 배치한다.

## 5. 소리와 호흡

이번 분석으로 확인한 것은 오디오 클립의 배치·종류·전환 위치다. 네 편 전체를 청취하거나 실제 믹스의 LUFS/피크를 측정한 것은 아니므로 레퍼런스의 음량 수치를 추정하지 않는다.

2026-10-30 추가 검수에서는 네 편의 Lumina 합성 프레임을 확인했다. 오디오 입력은 세션에서 지원되지 않아 직접 청취는 수행하지 못했다. 따라서 아래 소리 규칙은 실행·검수 지침이며, 네 편에서 듣고 입증한 성향으로 취급하지 않는다. 상세 범위는 Lumina 화면 검수（로컬 참조: `D:/Dev/lumina/docs/longform-editing/reference-benchmark/lumina-review/README.md`）를 따른다.

- 내레이션 이해를 최우선으로 한다. 원작 대사는 내레이션과 역할이 겹치지 않게 배치한다. 레제 41.29~44.17초의 원작 보컬 삽입처럼 말 자체가 증거일 때 살린다.
- BGM은 챕터·감정의 지속을 맡는다. 동일 파일이 여러 클립으로 나뉘어 있다고 곡 전환으로 세지 않는다.
- 호시노의 219.22초, 359.57초, 481.15초와 레제의 165.58초, 406.11초처럼 실제 곡/배치가 달라지는 지점을 논점과 함께 살펴본다. 정해진 분마다 바꾸는 규칙으로 일반화하지 않는다.
- 효과음은 등장·핵심 공개·반응에 의미를 더할 때 쓴다. 모든 컷·자막마다 넣지 않는다. 반복 Hit/Whoosh는 피로도와 내레이션 가림을 재생으로 점검한다.
- 무거운 서사에서는 효과를 덜어 감정이 유지되는지 비교한다. 조용한 구간도 의도적인 선택이다.
- 음성의 주도권을 계획표에 적는다: 내레이션 → 원작 대사 → 내레이션 복귀. 원작 대사의 시작 음절·끝말이 잘리지 않는지, 복귀한 내레이션이 효과음 꼬리에 가려지지 않는지 실제 청취로 확인한다. 단순히 트랙이 겹치지 않는 것만으로 합격시키지 않는다.
- 강조가 반복될 때는 소리의 강도를 구분한다. 작은 항목 추가, 논점 전환, 결론 공개에 같은 타격음을 같은 세기로 반복하는 규칙을 만들지 않는다. 무음 대안과 비교하고, 필요한 소리를 남긴다.
- 믹스의 피크/LUFS는 클리핑·과도한 음량 차이를 찾는 보조 자료다. 말의 명료도·감정·전환의 자연스러움은 수치만으로 검증할 수 없다.

## 6. 원본보다 발전시키는 검증

첫 자동 편집은 도입·설명·비교가 포함된 60~90초 구간으로 검증한 뒤 확장한다. 이는 사용자 승인 절차를 새로 만드는 것이 아니라 스스로 결과를 검증하는 작업 순서다. 사용자에게 허락을 반복해서 묻지 않는다.

아래 항목을 원본과 자동안 모두 평가한다:

- 대상 일치: 내레이션이 가리키는 것이 제때 보이는가?
- 읽기: 자막·숫자·자료를 정상 속도에서 이해할 수 있는가?
- 연결: 문장·동작이 불필요하게 끊기지 않는가?
- 리듬: 긴 유지와 짧은 공개에 각각 이유가 있는가?
- 절제: 강조·움직임·효과음을 빼도 전달되는 곳은 덜었는가?
- 신뢰성: 이미지가 실제 근거인지, 비유·추론인지 오해하지 않는가?

정량 지표는 경고를 찾는 데만 쓴다. 자막 수, 1초 미만 비율, 전환 수가 원본과 가까워지는 것을 최종 목표로 삼지 않는다.

# 롱폼 자막 문장 분할 기준 v1

최신 공통 기준: 자막 완료 기준（로컬 참조: `D:/Dev/lumina/docs/editing-grammar/caption-quality.md`）. 초반 공백·끝 문장부호·긴 자막 후처리를 포함하며 아래 과거 관찰보다 우선한다. Phrase 관련 구현 언급은 과거 이력이며 현행 도구는 Lumina 내부 speech다.

## 사용자 확정 화면 기준 — 2026-10-30 추가

이 기준은 아래의 글자 수 기반 초기 제안보다 우선한다.

- 폰트: **Pretendard Medium**, 크기 **60**, 자간 **-20** (Premiere UI 값).
- 사용자가 제공한 Premiere 스크린샷의 바운딩 박스를 기본 폭으로 삼는다. 후속 조사에서 호시노 **인계 파일 / 시퀀스 09**의 Pretendard-Medium 60, tracking -20, **1440×324** 박스를 직접 확인했다. 기본 폭 1440px은 이제 프로젝트 근거가 있다. 이 높이가 실제 자막의 허용 줄 수를 확정하는 것은 아니다.
- 어색한 위치에서 줄이 넘어가면 **박스를 좌우로 조금 확장할 수 있다.** 의미 단위를 희생하면서 기준 폭이나 글자 수를 기계적으로 맞추지 않는다. 최대 확장 폭은 아직 정하지 않았다.
- 분할 판단은 해당 폰트·크기·자간에서의 실제 렌더링 폭을 기준으로 한다. 공백 제외 글자 수는 보조 지표다. 한글·영문·숫자·공백의 실제 폭이 다르므로 30자 초과만으로 과병합이라고 판정하지 않는다.
- 스크린샷의 여러 줄 Lorem Ipsum은 박스의 개행 폭을 설명하는 참고다. 이를 실제 자막의 허용 줄 수로 해석하지 않는다. 화면 내부 줄바꿈과 시간상 자막 교체도 구분한다.
- Premiere의 자간 -20을 다른 렌더러의 -20px로 그대로 옮기지 않는다. 해당 렌더러의 자간 단위와 실제 줄넘김 결과를 대조해야 한다.

호시노 감사에서 확인한 `들고 / 온`, `해결하지 / 못했던`, 문장 종결 누락은 폭과 별개로 수정할 문제다. 반면 30자 이상이라는 이유만으로 표시한 긴 자막은 이 화면 기준으로 다시 평가한다. 현재 Phrase Studio 분할기에는 폰트 폭 측정이 아직 구현되어 있지 않다.

2026-10-30. 사용자 요청: 쇼츠보다 널널하게 나눈다. **한 장에 하나의 의미 덩어리(짧은 문장 또는 절)를 유지한다.** 글자 수는 분할을 검토하는 신호이며 강제 절단점이 아니다.

원본 경로 (위 루트 기준):

- `블루 아카이브\아비도스 고등학교\타카나시 호시노\타카나시 호시노.srt`, 같은 폴더의 `.prproj`
- `주술회전\이시고리 류\이시고리 류.srt`, 같은 폴더의 `.prproj`
- `체인소맨\덴지\덴지.srt`, 같은 폴더의 `덴지.prproj`
- `체인소맨\레제\Long\레제 롱폼.srt`, 같은 폴더의 `reze.prproj`

Lumina의 `lumina.io.prproj.extract`로 프로젝트를 읽어 네 SRT가 자막 에셋으로 들어 있으며 개수가 각각 425/160/218/167인 것을 확인했다. 이 리더는 타임라인의 네이티브 자막 트랙은 건너뛴다. 따라서 이 숫자를 최종 편집본 전수 측정이라고 부르지 않는다. 호시노의 그래픽으로 변환된 자막은 직접 읽고 SRT와 대조했다. 렌더 화면·오디오 검수는 이번 조사에 포함하지 않았다.

`덴지\SEQ.srt`는 색/밑줄 태그, 같은 문장의 스타일 변화로 나뉜 큐가 있어 기본 통계에서 제외했다. `레제 유튜브.srt`는 별도 버전(131개, 문자 중앙값 27, 시간 중앙값 3.96초)이며 화면용 자막과 동일하다고 확인되지 않아 제외했다. '호시노'는 이 문서에서 타카나시 호시노를 뜻한다.

## 실제 편집에서 확인한 경계

`/`는 자막 교체이며 화면 안 줄바꿈과 다르다.

- 레제 9.97초: `레제는 단순히 예쁜 캐릭터가 아닙니다` — 짧은 완결문을 유지한다.
- 레제 12.59초: `그녀는 독자가 그리고 덴지가 사랑에 빠질 수밖에 없도록 / 정교하게 만들어진 캐릭터이죠` — 긴 수식절 뒤에서 나눈다.
- 덴지 63.24초: `그런데 톱날이 그냥 붙는 게 아니라 살점을 찢고 나옵니다` — 접속 표현과 대조 구문이 있다고 무조건 나누지 않는다.
- 호시노 편집 그래픽 58.56초: `여기서 총의 이름은 호루스의 눈 / 방패는 아이언 호루스입니다` — 원본 SRT의 `여기서 총의 이름은 / 호루스의 눈 방패는 아이언 호루스입니다`보다 대상과 설명이 잘 묶였다. 자동화에서는 편집 그래픽 경계를 우선 참고한다.
- 호시노 편집 그래픽 21.23초: `이 친구가 어떻게 / 블루 아카이브를 대표하는 캐릭터 중에 / 하나가 될 수 있었을까요?` — SRT에 통째로 있던 긴 질문도 실제 편집에서는 나뉜다. 널널하게 유지하는 것과 긴 문장을 전부 한 장에 넣는 것은 다르다.
- 호시노 도입 0~2.68초: `블루 아카이브에는 / 이상한 친구가 / 하나 있습니다` — 도입의 짧은 리듬은 예외로 인정한다. 이 패턴을 본문 기본값으로 쓰지 않는다.

## 자동화 기본값 — 관측값에서 제안한 초기 정책

아래 숫자는 사용자 확정값이나 학습된 최적값이 아니라 위 표본에 기반한 v1이다.

1. **문장 끝을 우선 경계로 둔다.** 짧은 완결문은 한 장에 둔다. 서로 다른 문장을 글자 수를 채우기 위해 합치지 않는다.
2. **기본 목표는 공백 제외 12~24자, 표시 1.5~3.5초.** 덴지 정도의 호흡을 중심으로 삼되, 레제처럼 설명이 이어지면 25~30자·4~5초도 허용한다. 목표보다 짧다고 무조건 합치거나 길다고 무조건 나누지 않는다.
3. **30자 초과 또는 5초 초과는 재검토 플래그.** 긴 인용·열거는 예외로 유지할 수 있으나, 우선 절·항목·대상 전환 위치에서 나눌 수 있는지 본다. 원본 레제의 8초 이상 큐를 일반 기본값으로 삼지 않는다.
4. **1초 미만의 불완전한 조각은 이웃과 병합을 우선 검토한다.** `그런데`, `그리고`, `즉`, `그는` 등을 습관적으로 독립시키지 않는다. 문장·화자·장면상의 의미 전환을 넘겨 합치지 않는다. 짧은 질문, 이름 공개, 반응, 도입의 의도적인 리듬은 예외다.
5. **절 경계는 후보일 뿐이다.** `-고/-는데/-지만/-면/-도록`마다 자르지 않는다. 한 장으로 읽을 만하면 유지하고, 길거나 다음 대상·주장으로 넘어갈 때 나눈다. TTS의 쉼만으로 결정하지 않는다.
6. **문법적으로 붙어야 하는 덩어리를 지킨다.** 고유명사, 수+단위, 명사+조사, 짧은 관형어+명사, 본용언+보조용언을 끊지 않는다. 짧은 주어+서술어·목적어+동사는 가능한 한 함께 둔다. 긴 수식절은 의미가 분명한 경계에서 나눌 수 있다.
7. **강조할 단어 때문에 자막을 쪼개지 않는다.** 롱폼에서는 문장을 유지하고 색·밑줄·별도 그래픽으로 강조할 수 있다. 효과나 영상 컷 경계가 곧 자막 교체 경계는 아니다.
8. **화면 줄바꿈과 시간 분할을 별도로 처리한다.** 글자 수로 화면 적합성을 보장할 수 없다. 선택한 폰트·크기·실제 박스 폭으로 확인하고 의미 단위 줄바꿈 또는 시간 분할을 선택한다. 이번 조사로 1줄 고정이나 최대 줄 수는 확정하지 않는다.

## 따라 하지 않을 원본 경계

- 덴지 230.83초 큐가 `…책임감으로 살지만 료멘`으로 끝난다. `료멘 스쿠나`처럼 고유명사가 걸쳐지는 경계는 보호한다.
- 이시고리 76.09초 `거칠게 뭉쳐있는 게 특징입니다 즉,`에서 `즉,`은 다음 설명으로 옮기는 것이 자연스럽다.
- 호시노의 총·방패 예처럼 SRT와 편집 그래픽 경계가 다르면 수작업으로 의미를 다듬은 그래픽 사례를 우선한다.
- 원본의 오탈자는 분할 기준 학습과 별개다. 잘못된 표기나 경계를 정답으로 재생산하지 않는다.

## 구현·검수 순서

1. 롱폼 전용 모드를 만든다. 쇼츠의 짧은 구절 기준이나 `≤4단어/14자` 사전 줄바꿈 판정을 롱폼에 그대로 쓰지 않는다.
2. 문장/화자 경계와 보호 구문을 먼저 찾고, 절·열거 경계를 후보로 만든다.
3. 의미 보존을 우선해 묶고 위 길이·시간 범위로 재검토한다. 실제 단어 타임스탬프에 맞춘다. 글자 수 비례로 시간을 자르지 않는다.
4. 짧은 불완전 조각과 고유명사 분단을 확인한다. 사용자 명시 분할과 의도적인 공개·반응 타이밍은 보존한다.
5. 첫 적용에서는 도입·설명 본문·긴 인용을 포함한 구간을 렌더와 음성으로 검수한다. 원본 대비 과분할/과병합 사례를 기록한 뒤 기본값을 조정한다.

초기 조사 당시 완료 범위는 기준 문서화였다. 이후 Phrase Studio 롱폼 v1을 구현했고 호시노 분할 감사（로컬 참조: `D:/Dev/lumina/docs/longform-editing/hoshino-audit/README.md`）에서 의미 경계 오류를 확인했다. 이 문서의 최신 화면 기준(실제 폰트 폭)은 아직 분할기에 구현되지 않았다. 원본 프로젝트 자막은 변경하지 않았다.
