# 롱폼 자막 문장 분할 기준 v1

최신 공통 기준: [자막 완료 기준](../editing-grammar/caption-quality.md). 초반 공백·끝 문장부호·긴 자막 후처리를 포함하며 아래 과거 관찰보다 우선한다. Phrase 관련 구현 언급은 과거 이력이며 현행 도구는 Lumina 내부 speech다.

## 사용자 확정 화면 기준 — 2026-10-30 추가

이 기준은 아래의 글자 수 기반 초기 제안보다 우선한다.

- 폰트: **Pretendard Medium**, 크기 **60**, 자간 **-20** (Premiere UI 값).
- 사용자가 제공한 Premiere 스크린샷의 바운딩 박스를 기본 폭으로 삼는다. 후속 조사에서 호시노 **인계 파일 / 시퀀스 09**의 Pretendard-Medium 60, tracking -20, **1440×324** 박스를 직접 확인했다. 기본 폭 1440px은 이제 프로젝트 근거가 있다. 이 높이가 실제 자막의 허용 줄 수를 확정하는 것은 아니다.
- 어색한 위치에서 줄이 넘어가면 **박스를 좌우로 조금 확장할 수 있다.** 의미 단위를 희생하면서 기준 폭이나 글자 수를 기계적으로 맞추지 않는다. 최대 확장 폭은 아직 정하지 않았다.
- 분할 판단은 해당 폰트·크기·자간에서의 실제 렌더링 폭을 기준으로 한다. 공백 제외 글자 수는 보조 지표다. 한글·영문·숫자·공백의 실제 폭이 다르므로 30자 초과만으로 과병합이라고 판정하지 않는다.
- 스크린샷의 여러 줄 Lorem Ipsum은 박스의 개행 폭을 설명하는 참고다. 이를 실제 자막의 허용 줄 수로 해석하지 않는다. 화면 내부 줄바꿈과 시간상 자막 교체도 구분한다.
- Premiere의 자간 -20을 다른 렌더러의 -20px로 그대로 옮기지 않는다. 해당 렌더러의 자간 단위와 실제 줄넘김 결과를 대조해야 한다.

호시노 감사에서 확인한 `들고 / 온`, `해결하지 / 못했던`, 문장 종결 누락은 폭과 별개로 수정할 문제다. 반면 30자 이상이라는 이유만으로 표시한 긴 자막은 이 화면 기준으로 다시 평가한다. 현재 Phrase Studio 분할기에는 폰트 폭 측정이 아직 구현되어 있지 않다.

2026-10-30. 사용자 요청: 쇼츠보다 널널하게 나눈다. **한 장에 하나의 의미 덩어리(짧은 문장 또는 절)를 유지한다.** 글자 수는 분할을 검토하는 신호이며 강제 절단점이 아니다.

`D:\유튜브 채널\Project` 아래 네 SRT 전체 970개를 측정했다. 공백·개행 제외, 문장부호 포함 문자 수이며 시간은 SRT 표시 길이다. 발화 길이나 음성의 실제 쉼을 측정한 값은 아니다. 아래 범위는 10~90백분위다.

Lumina의 `lumina.io.prproj.extract`로 프로젝트를 읽어 네 SRT가 자막 에셋으로 들어 있으며 개수가 각각 425/160/218/167인 것을 확인했다. 이 리더는 타임라인의 네이티브 자막 트랙은 건너뛴다. 따라서 이 숫자를 최종 편집본 전수 측정이라고 부르지 않는다. 호시노의 그래픽으로 변환된 자막은 직접 읽고 SRT와 대조했다. 렌더 화면·오디오 검수는 이번 조사에 포함하지 않았다.

`덴지\SEQ.srt`는 색/밑줄 태그, 같은 문장의 스타일 변화로 나뉜 큐가 있어 기본 통계에서 제외했다. `레제 유튜브.srt`는 별도 버전(131개, 문자 중앙값 27, 시간 중앙값 3.96초)이며 화면용 자막과 동일하다고 확인되지 않아 제외했다. '호시노'는 이 문서에서 타카나시 호시노를 뜻한다.

## 실제 편집에서 확인한 경계

`/`는 자막 교체이며 화면 안 줄바꿈과 다르다.

- 레제 9.97초: `레제는 단순히 예쁜 캐릭터가 아닙니다` — 짧은 완결문을 유지한다.
- 레제 12.59초: `그녀는 독자가 그리고 덴지가 사랑에 빠질 수밖에 없도록 / 정교하게 만들어진 캐릭터이죠` — 긴 수식절 뒤에서 나눈다.
- 덴지 63.24초: `그런데 톱날이 그냥 붙는 게 아니라 살점을 찢고 나옵니다` — 접속 표현과 대조 구문이 있다고 무조건 나누지 않는다.
- 호시노 편집 그래픽 58.56초: `여기서 총의 이름은 호루스의 눈 / 방패는 아이언 호루스입니다` — 원본 SRT의 `여기서 총의 이름은 / 호루스의 눈 방패는 아이언 호루스입니다`보다 대상과 설명이 잘 묶였다. 자동화에서는 편집 그래픽 경계를 우선 참고한다.
- 호시노 편집 그래픽 21.23초: `이 친구가 어떻게 / 블루 아카이브를 대표하는 캐릭터 중에 / 하나가 될 수 있었을까요?` — SRT에 통째로 있던 긴 질문도 실제 편집에서는 나뉜다. 널널하게 유지하는 것과 긴 문장을 전부 한 장에 넣는 것은 다르다.
- 호시노 도입 0~2.68초: `블루 아카이브에는 / 이상한 친구가 / 하나 있습니다` — 도입의 짧은 리듬은 예외로 인정한다. 이 패턴을 본문 기본값으로 쓰지 않는다.

## 자동화 기본값 — 관측값에서 제안한 초기 정책

아래 숫자는 사용자 확정값이나 학습된 최적값이 아니라 위 표본에 기반한 v1이다.

1. **문장 끝을 우선 경계로 둔다.** 짧은 완결문은 한 장에 둔다. 서로 다른 문장을 글자 수를 채우기 위해 합치지 않는다.
2. **기본 목표는 공백 제외 12~24자, 표시 1.5~3.5초.** 덴지 정도의 호흡을 중심으로 삼되, 레제처럼 설명이 이어지면 25~30자·4~5초도 허용한다. 목표보다 짧다고 무조건 합치거나 길다고 무조건 나누지 않는다.
3. **30자 초과 또는 5초 초과는 재검토 플래그.** 긴 인용·열거는 예외로 유지할 수 있으나, 우선 절·항목·대상 전환 위치에서 나눌 수 있는지 본다. 원본 레제의 8초 이상 큐를 일반 기본값으로 삼지 않는다.
4. **1초 미만의 불완전한 조각은 이웃과 병합을 우선 검토한다.** `그런데`, `그리고`, `즉`, `그는` 등을 습관적으로 독립시키지 않는다. 문장·화자·장면상의 의미 전환을 넘겨 합치지 않는다. 짧은 질문, 이름 공개, 반응, 도입의 의도적인 리듬은 예외다.
5. **절 경계는 후보일 뿐이다.** `-고/-는데/-지만/-면/-도록`마다 자르지 않는다. 한 장으로 읽을 만하면 유지하고, 길거나 다음 대상·주장으로 넘어갈 때 나눈다. TTS의 쉼만으로 결정하지 않는다.
6. **문법적으로 붙어야 하는 덩어리를 지킨다.** 고유명사, 수+단위, 명사+조사, 짧은 관형어+명사, 본용언+보조용언을 끊지 않는다. 짧은 주어+서술어·목적어+동사는 가능한 한 함께 둔다. 긴 수식절은 의미가 분명한 경계에서 나눌 수 있다.
7. **강조할 단어 때문에 자막을 쪼개지 않는다.** 롱폼에서는 문장을 유지하고 색·밑줄·별도 그래픽으로 강조할 수 있다. 효과나 영상 컷 경계가 곧 자막 교체 경계는 아니다.
8. **화면 줄바꿈과 시간 분할을 별도로 처리한다.** 글자 수로 화면 적합성을 보장할 수 없다. 선택한 폰트·크기·실제 박스 폭으로 확인하고 의미 단위 줄바꿈 또는 시간 분할을 선택한다. 이번 조사로 1줄 고정이나 최대 줄 수는 확정하지 않는다.

## 따라 하지 않을 원본 경계

- 덴지 230.83초 큐가 `…책임감으로 살지만 료멘`으로 끝난다. `료멘 스쿠나`처럼 고유명사가 걸쳐지는 경계는 보호한다.
- 이시고리 76.09초 `거칠게 뭉쳐있는 게 특징입니다 즉,`에서 `즉,`은 다음 설명으로 옮기는 것이 자연스럽다.
- 호시노의 총·방패 예처럼 SRT와 편집 그래픽 경계가 다르면 수작업으로 의미를 다듬은 그래픽 사례를 우선한다.
- 원본의 오탈자는 분할 기준 학습과 별개다. 잘못된 표기나 경계를 정답으로 재생산하지 않는다.

## 구현·검수 순서

1. 롱폼 전용 모드를 만든다. 쇼츠의 짧은 구절 기준이나 `≤4단어/14자` 사전 줄바꿈 판정을 롱폼에 그대로 쓰지 않는다.
2. 문장/화자 경계와 보호 구문을 먼저 찾고, 절·열거 경계를 후보로 만든다.
3. 의미 보존을 우선해 묶고 위 길이·시간 범위로 재검토한다. 실제 단어 타임스탬프에 맞춘다. 글자 수 비례로 시간을 자르지 않는다.
4. 짧은 불완전 조각과 고유명사 분단을 확인한다. 사용자 명시 분할과 의도적인 공개·반응 타이밍은 보존한다.
5. 첫 적용에서는 도입·설명 본문·긴 인용을 포함한 구간을 렌더와 음성으로 검수한다. 원본 대비 과분할/과병합 사례를 기록한 뒤 기본값을 조정한다.

초기 조사 당시 완료 범위는 기준 문서화였다. 이후 Phrase Studio 롱폼 v1을 구현했고 [호시노 분할 감사](hoshino-audit/README.md)에서 의미 경계 오류를 확인했다. 이 문서의 최신 화면 기준(실제 폰트 폭)은 아직 분할기에 구현되지 않았다. 원본 프로젝트 자막은 변경하지 않았다.
