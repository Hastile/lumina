# 공통 기준 — 기획·근거·문체·수정

2026-11-01 · 통합본 v1.5. 채널 콘텐츠 v4와 문체 v2.2, 대본·편집 공통 규칙을 이 문서로 통합했다.

## 1. 무엇을 만드는가

고정된 축은 **설계 의도와 구현을 해부하는 질문**, 바뀔 수 있는 것은 작품·소재·형식이다. 캐릭터의 외형뿐 아니라 명명·상징·연출·서사·제작 원리·배경·세계관도 다룬다. 단일 IP에 채널을 고정하지 않는다. 해설·비교·나열·참여형 모두 가능하며, 형식을 먼저 고른 뒤 내용을 끼워 넣지 않는다.

작품을 모르는 사람은 지금 보이는 현상에서 들어오고, 팬은 알고 있던 장면을 새롭게 볼 이유를 얻어야 한다. 뉴스·출시 소식·업데이트·평점 소개만으로 끝내지 않는다. 원작의 재미를 옮기는 리캡·명장면 나열, 물량 경쟁, 작품명에만 기대는 후킹을 목표로 삼지 않는다.

쇼츠는 피드에서 처음 만나는 사람과 팬이 섞여 한 번, 순서대로 본다. 롱폼은 관심을 갖고 클릭했지만 작품과 분석 개념의 이해도가 서로 다르다. 고정댓글은 영상을 본 사람이 추가 근거 하나를 얻으러 읽는다. 연령·유입·성과 숫자는 06의 과거 표본이지 현재 상태가 아니다.

## 2. 근거와 조사

작성 전 핵심 질문과 시청자가 얻을 답을 한 문장으로 정한다. 고유명사·번역·화수·원작/애니 차이·제작진 발언·어원·문화적 배경·반응·실제 화면 확보 여부를 확인한다. 이미 충분한 자료가 있거나 지정 문장만 교정하는 경우 불필요하게 조사를 다시 하지 않는다.

원작·공식 자료·직접 인터뷰를 우선하고 신뢰할 만한 2차 자료로 보완한다. 위키·커뮤니티는 탐색 단서이며 핵심 사실을 단독 확정하는 근거로 삼지 않는다. 시점에 따라 달라지는 사실은 기준일과 현재성을 확인한다. 확보한 자료가 없으면 없다고 남긴다.

| 주장 | 말할 수 있는 범위 |
|---|---|
| 사실 | 자료에서 직접 확인한 내용 |
| 관찰 | 실제 화면·소리·문구에서 확인한 특징과 반복 |
| 제작 의도 | 제작진이 직접 밝힌 범위. 발언보다 동기를 넓히지 않음 |
| 해석 | 확인된 사실·관찰을 연결한 분석. 공식 설정처럼 단정하지 않음 |
| 가설 | 근거와 검증 한계가 있는 잠정 설명 |
| 미확인 | 확인이 필요한 주장. 그럴듯한 어미로 살리지 않음 |

공식 문장에 없는 연결도 콘텐츠가 될 수 있지만 연결의 재료는 성립해야 한다. 원문이 '옛날 애니'면 임의로 '90년대'라고 쓰지 않는다. 따로 확인한 두 사실을 '논의했지만 최종적으로는'으로 묶어 하나의 선택·인과로 만들지 않는다. 인기의 존재와 인기의 원인, 브랜드 아이덴티티와 실제 이미지, 모티프와 단순 유사성을 구분한다.

인용은 원문과 맥락을 확인한다. 직접 인용과 요약·의역을 구별하고 사용할 수 있는 인용 범위를 지킨다. 출처 자체가 이야기의 핵심일 때만 내레이션에서 짧게 밝히고 나머지는 자료 메모·설명란·고정댓글로 보낸다. 출처를 숨기지도, 출처 설명이 본론보다 앞서게 하지도 않는다.

커뮤니티 반응을 주장할 때는 실제 원문 게시물·작성 시점·해당 댓글/반응을 연결하고 관찰한 범위를 적는다. 일부 팬의 비판이나 특정 게시판의 반응을 전체 팬 여론·제작 의도로 확대하지 않는다. 검색 요약·재인용만 확보했다면 원문 미확인으로 남긴다.

## 3. 문체의 목표

**정확성·자연스러움·전달력을 함께 지킨다. 잘 쓴 척하는 문장 대신 정확한 내용을 자연스러운 한국어로 말한다.** 차분한 한국어 해설을 기본으로 하되 필요한 문어체·격식체·복문·전문어를 보존한다. 구어체 비율이나 문장 길이로 자연스러움을 판정하지 않는다.

- 어휘 결합, 주어·서술어 호응, 수식 범위, 지시 대상, 인과·대조를 실제 문장 안에서 확인한다. '실제로', '기능한다', '이는', '~것', '~라고 할 수 있다'는 금칙어가 아니다.
- 부정·대조는 실제 오해나 차이가 있을 때 쓴다. '장식이 아니라 정체성'처럼 서로 다른 층위를 맞세워 중요성을 부풀리지 않는다. 실제 어긋남은 회피하지 않는다.
- '굉장히 특별하다', '많은 팬이 놀랐다', '매력을 끌어올린다'로 관찰을 대신하지 않는다. 무엇이 어떻게 달라졌는지, 어떤 근거가 있는지 말한다.
- '하지만/반면'에는 대조, '그래서/때문에'에는 인과, '즉'에는 재진술, '오히려'에는 기대와 반대되는 방향이 있어야 한다. 시간 순서를 인과로 만들지 않는다.
- 지시어가 모호할 때만 명사를 밝힌다. 자연스러운 피동·무생물 주어·명사화·복문을 일괄 제거하지 않는다. 능동으로 바꾸면서 확인되지 않은 행위자나 동기를 추가하지 않는다.
- '에어인테이크 같은 모양'을 '에어인테이크 역할'로 바꾸지 않는다. 기능·의미·명칭의 범주와 확실성 수준을 번역·윤문 중에 바꾸지 않는다.
- 진행 멘트가 새 내용을 예고만 하면 바로 내용을 말한다. 필요한 질문·화면 안내·장 전환·요약은 유지한다. 롱폼 고정 진입 문장은 02의 명시적 예외다.
- 기사 요약 말투를 이어 붙이지 않는다. 제작진의 말은 정확한 짧은 직접 인용이나 자연스러운 해설로 처리한다. 출처가 있다는 사실이 의도·효과의 증명은 아니다.
- 한 결론을 예고→설명→유사어 재진술→감상으로 늘리지 않는다. 의도된 회수와 필요한 종합은 허용한다.
- 같은 어미를 피하려고 무작위로 바꾸지 않는다. 반말·유행어·'거든요/잖아요/죠'를 친근함 장식으로 넣지 않는다. 정보와 호흡에 따라 문장 길이가 달라지게 한다.
- 전문 개념을 '매력/느낌/뭔가'로 뭉개지 않는다. 조건과 해석의 유보는 필요한 곳에 유지하며 같은 한계를 문단마다 반복하지 않는다. 명백한 사실을 습관적인 추측형으로 흐리지 않는다.

단어 검색은 의심 위치를 찾는 보조 수단이다. 자동 일괄 치환, 임의의 어미 비율·횟수 제한·한 문장 글자 수 규칙은 쓰지 않는다. 06의 가상 예문은 문체 판정용이며 실제 작품 자료가 아니다.

## 4. 수정 권한과 확정본 보호

| 요청 | 할 일 | 보존할 것 |
|---|---|---|
| 진단·UX·뜯어보기 | 듣는 순서대로 실제 문제와 수정본 제시 | 정상 문장·핵심 관찰 |
| 문체 수정 | 표현과 직접 연결된 앞뒤 문장만 수정 | 논지·구성·사실 범위 |
| 특정 구간만 | 지정 구간 수정, 불가피한 연결 수정은 명시 | 나머지 구간 |
| 전체 재작성 | 핵심 관찰을 살려 구성·문장을 폭넓게 개선 | 근거의 범위·명시적 고정 사항 |
| 문장 픽스·확정 | 다음 작업에서도 잠금으로 취급 | 정확한 문구·순서·어미 |
| TTS 태그만 | 확정 원문에 태그만 부착 | 글자·어미·고유명사·마지막 문장 |
| 영상 편집 | 확정 대본을 화면·소리·캡션으로 구현 | 승인 없이 원고를 삭제·재작성하지 않음 |

개선 이유가 없으면 원문을 유지한다. 새 문장이 정확성·자연스러움·전달력 중 하나를 개선하되 나머지를 훼손하지 않아야 한다. 사실 오류 정정과 문체 수정을 구분해 알린다. 승인되지 않은 제안이나 가상 예시를 사용자 확정 취향으로 기록하지 않는다.

## 5. 한 줄씩 검수하고 역검수한다

쓰는 순서는 인터뷰·리서치 목차가 아니라 **시청자가 보는 것 → 그것이 무엇인지 → 왜 그런지**다. 매 줄에서 '지금까지 들은 것만으로 이해되는가, 화면에서 찾을 수 있는가, 앞뒤가 이어지는가'를 확인한다. 미래 문장의 설명을 이미 아는 것처럼 판단하지 않는다.

제출 전 의미 보존 → 번역투 → 구체적 근거 → 논리·호응 → 낭독·화면 → 불필요한 문장 제거 → 원문과 역대조 순으로 검수한다. 개선되지 않았으면 원문으로 되돌린다. 이 과정은 내부에서 끝내고, 기본 출력에 검사표를 덧붙이지 않는다.

문제를 보고할 때는 'AI 같다/UX가 약하다' 대신 '이 문장을 들으면 눈 대신 입을 개조했다고 이해하게 된다'처럼 실제 오해를 설명한다. 진단은 손볼 핵심 몇 개와 수정본으로 마친다. 사용자가 원하면 상세 근거를 별도로 제공한다.
