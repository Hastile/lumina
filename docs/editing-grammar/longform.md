# 롱폼 편집 문법

공통 컷 판단은 [common-cuts.md](common-cuts.md)를 따른다. 이 문서는 긴 설명에서 기억·정보량·호흡을 관리하는 방법을 추가한다.

## 1. 구조: 장식보다 논점의 진행

작품마다 같은 목차를 강제하지 않는다. 네 참고작에서 관찰한 외형/모티브/서사/비교/분석의 이동을 활용하되, 대본의 질문을 가장 잘 풀어주는 순서를 고른다.

- 도입: 이번에 알아볼 질문과 시각적 특징을 빠르게 연결한다. 레제의 원작 대사 도입처럼 목소리·사건 자체가 질문을 만드는 방식도 허용한다.
- 설명: `주장 → 화면 증거 → 해석`이 연결되도록 한다. 출처 화면을 보여줬다는 사실만으로 주장의 근거가 충분해지는 것은 아니다.
- 전환: 논점이 바뀌면 시청자가 위치를 이해하도록 화면·짧은 타이틀·음악 중 필요한 수단을 선택한다. 매 챕터마다 모두 동원하지 않는다.
- 결론: 앞선 증거를 묶어 도입 질문에 답한다. 이미 본 장면을 재사용할 때는 새 요약·비교의 역할이 있어야 한다.

## 2. 설명 유형별 화면 선택

| 설명 유형 | 권장 화면 | 피할 것 |
|---|---|---|
| 외형·색·소품 | 전체 실루엣 → 해당 부위/물건, 필요하면 색칩·짧은 표시 | 인물 얼굴만 반복하면서 소품 설명 |
| 크기·차이 비교 | 동시 배치, 기준선/동일 확대율, 라벨 | 크기가 다른 원본을 그대로 놓고 우열을 암시 |
| 명칭·어원·모티브 | 용어 → 실제 대상 → 연결점 | 이름이 비슷하다는 이유만으로 유래를 확정 |
| 서사 사건 | 실제 사건의 준비·행동·결과 | 다른 사건을 그 사건처럼 보이게 붙임 |
| 추상 분석 | 구체적인 사례 뒤 핵심어를 누적 | 분석 용어를 큰 글자로만 반복 |
| 숫자·매출·인용 | 해당 수치/문장 확대 + 출처 유지 | 기사 전체 축소 화면으로 검증을 대신함 |
| 유머·반응 | 맥락을 해치지 않는 짧은 반응과 복귀 | 다음 설명을 덮는 밈·효과음 |

호시노의 산탄총 설명은 실제 장전 부위를 보여주는 방식, 이시고리의 디저트 모티브는 실제 디저트 이미지, 덴지의 전기톱 색은 실제 제품 비교를 활용한다. 이를 발전시키려면 설명 부위와 비교 축을 더욱 분명히 하고 불필요한 검색 화면·부연을 줄인다.

## 3. 자막과 그래픽의 역할 분리

- 기본 자막: **Pretendard Medium 60, 자간 -20**. 호시노 완성본 `시퀀스 09`에서 실제 박스 **1440×324**를 확인했다. 기본 폭 1440은 근거가 있으며 애매한 개행은 사용자 허용대로 좌우 확장 가능하다. 확장 상한은 아직 미정이다.
- 자막 위치는 렌더 결과와 화면 내용을 보고 정한다. Premiere 추출의 로컬 좌표를 Lumina 최종 화면 좌표로 그대로 복사하지 않는다.
- 글자 수가 아닌 실제 폰트 폭을 우선한다. 30자/5초는 재검토 신호이지 탈락 조건이 아니다. 현재 Phrase Studio v1은 폭 측정을 하지 않으며 호시노 감사에서 종결·결합 표현 오류가 확인됐으므로 결과를 자동 확정하지 않는다.
- 박스 내부 개행과 시간상 자막 교체를 구분한다. 붙어야 할 표현을 분리하거나 무조건 폰트를 줄여 해결하지 않는다. 기본 허용 줄 수는 아직 확정하지 않았다.
- 이름표는 누가 누구인지, 강조어는 무엇을 볼지, 보조 설명은 내레이션에서 생략한 짧은 정보를 맡는다. 세 층이 같은 문장을 중복해 보여주지 않게 한다.
- 호시노 완성본에는 Black 120/200 등도 보이지만 기본값으로 복제하지 않는다. 큰 강조는 짧은 공개·반전처럼 목적이 있는 경우만 사용한다. 쇼츠의 pop/slam/fade 비율을 롱폼에 강제하지 않는다.

## 4. 누적 설명과 비교 카드

이시고리 183.39~188.65초는 세 설명을 차례로 쌓고, 레제 457.25~465.30초는 STP의 대상을 순차 추가한다. **이미 이해한 항목을 화면에 남기고 새 항목만 추가**하는 방법은 긴 설명의 기억 부담을 낮출 수 있다.

개선 원칙:

1. 등장 순서는 말하는 순서와 맞춘다. 끝에 한꺼번에 뜨는 결과표보다 진행을 따라갈 수 있어야 한다.
2. 현재 설명하는 항목만 대비를 높이고 이전 항목은 남겨 비교할 수 있게 한다.
3. 마지막 상태에 읽고 비교할 시간이 필요하다. 해당 주장이 끝나기 전에 표를 치우지 않는다.
4. 글이 많으면 먼저 읽기 카드인지 회상 몽타주인지 구분한다. 덴지의 258.17~261.18초 SWOT 세 카드는 각각 약 1초에 여러 항목을 담으며, Lumina 합성 표본에서도 네 문장과 큰 약어가 확인됐다. 모든 항목의 읽기가 목적이면 핵심 축 하나를 충분히 읽히거나 설명 구간으로 분산한다. 회상 목적이면 이미 설명한 핵심어로 압축한다. 앞뒤 음성 미청취 상태에서는 원본의 의도를 확정하지 않는다.
5. 표를 만든다고 사건 영상까지 줄일 필요는 없다. 정적 비교 화면과 실제 행동 화면의 역할을 번갈아 배치한다.

## 5. 소리와 호흡

이번 분석으로 확인한 것은 오디오 클립의 배치·종류·전환 위치다. 네 편 전체를 청취하거나 실제 믹스의 LUFS/피크를 측정한 것은 아니므로 레퍼런스의 음량 수치를 추정하지 않는다.

2026-10-30 추가 검수에서는 네 편의 Lumina 합성 프레임을 확인했다. 오디오 입력은 세션에서 지원되지 않아 직접 청취는 수행하지 못했다. 따라서 아래 소리 규칙은 실행·검수 지침이며, 네 편에서 듣고 입증한 성향으로 취급하지 않는다. 상세 범위는 [Lumina 화면 검수](../longform-editing/reference-benchmark/lumina-review/README.md)를 따른다.

- 내레이션 이해를 최우선으로 한다. 원작 대사는 내레이션과 역할이 겹치지 않게 배치한다. 레제 41.29~44.17초의 원작 보컬 삽입처럼 말 자체가 증거일 때 살린다.
- BGM은 챕터·감정의 지속을 맡는다. 동일 파일이 여러 클립으로 나뉘어 있다고 곡 전환으로 세지 않는다.
- 호시노의 219.22초, 359.57초, 481.15초와 레제의 165.58초, 406.11초처럼 실제 곡/배치가 달라지는 지점을 논점과 함께 살펴본다. 정해진 분마다 바꾸는 규칙으로 일반화하지 않는다.
- 효과음은 등장·핵심 공개·반응에 의미를 더할 때 쓴다. 모든 컷·자막마다 넣지 않는다. 반복 Hit/Whoosh는 피로도와 내레이션 가림을 재생으로 점검한다.
- 무거운 서사에서는 효과를 덜어 감정이 유지되는지 비교한다. 조용한 구간도 의도적인 선택이다.
- 음성의 주도권을 계획표에 적는다: 내레이션 → 원작 대사 → 내레이션 복귀. 원작 대사의 시작 음절·끝말이 잘리지 않는지, 복귀한 내레이션이 효과음 꼬리에 가려지지 않는지 실제 청취로 확인한다. 단순히 트랙이 겹치지 않는 것만으로 합격시키지 않는다.
- 강조가 반복될 때는 소리의 강도를 구분한다. 작은 항목 추가, 논점 전환, 결론 공개에 같은 타격음을 같은 세기로 반복하는 규칙을 만들지 않는다. 무음 대안과 비교하고, 필요한 소리를 남긴다.
- 믹스의 피크/LUFS는 클리핑·과도한 음량 차이를 찾는 보조 자료다. 말의 명료도·감정·전환의 자연스러움은 수치만으로 검증할 수 없다.

## 6. 원본보다 발전시키는 검증

첫 자동 편집은 도입·설명·비교가 포함된 60~90초 구간으로 검증한 뒤 확장한다. 이는 사용자 승인 절차를 새로 만드는 것이 아니라 스스로 결과를 검증하는 작업 순서다. 사용자에게 허락을 반복해서 묻지 않는다.

아래 항목을 원본과 자동안 모두 평가한다:

- 대상 일치: 내레이션이 가리키는 것이 제때 보이는가?
- 읽기: 자막·숫자·자료를 정상 속도에서 이해할 수 있는가?
- 연결: 문장·동작이 불필요하게 끊기지 않는가?
- 리듬: 긴 유지와 짧은 공개에 각각 이유가 있는가?
- 절제: 강조·움직임·효과음을 빼도 전달되는 곳은 덜었는가?
- 신뢰성: 이미지가 실제 근거인지, 비유·추론인지 오해하지 않는가?

정량 지표는 경고를 찾는 데만 쓴다. 자막 수, 1초 미만 비율, 전환 수가 원본과 가까워지는 것을 최종 목표로 삼지 않는다.
