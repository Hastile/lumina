# Lumina 실행 — Chat·GPT Bridge·자막·저장

2026-10-31 기준 운영 절차. 도구명·인자·기능 지원 여부는 현재 연결의 실제 정의가 우선한다. 소스 코드나 지침을 업로드한 것으로 도구 연결을 대신할 수 없다.

## 1. 연결과 대상 확인

Chat → GPT Bridge → 로컬 Lumina MCP → Lumina GUI 경로를 사용한다. Lumina MCP는 로컬 stdio 서버다. Bridge는 중계·파일 작업, Lumina는 편집·대상 보호를 맡는다.

1. 파일 접근은 Bridge `get_workspace_info`로 등록 루트부터 확인한다.
2. `lumina_list_tools`로 필요한 도구 정의를 조회하고 `lumina_call_tool`로 호출한다.
3. `get_editor_status` → 필요한 경우 `ensure_editor(project_path)` → `list_projects` → `get_project` → 대상 `get_timeline_state` 순으로 실제 경로·활성 프로젝트·시퀀스 ID·fps·dirty를 확인한다.
4. 이미 열린 대상은 미저장 작업을 유지한 채 활성화한다. 다시 열기·다른 프로젝트 닫기로 덮어쓰지 않는다. 사용자에게 보여줄 시퀀스를 활성화하고 변경 명령에 대상 ID를 명시한다.

조회 요청은 읽기까지만 한다. 대본 작성·지침 수정 요청을 실제 영상 변경으로 확대하지 않는다. 편집 요청을 받은 작업은 작은 Undo 단위로 진행하며 통상적인 배치마다 다시 허락을 묻지 않는다.

## 2. 파일과 프로젝트

| 등록 이름 예 | 확인할 루트 / 목적 |
|---|---|
| default | D:/Dev — 개발·지침 |
| YouTube | D:/유튜브 채널 — 작품 프로젝트·소스 |
| Downloads | C:/Users/HETX/Downloads — 일반 다운로드 |
| Videos | C:/Users/HETX/Videos — 녹화 소스 |
| YouTubeVideos | C:/Users/HETX/Downloads/hitomi_downloader_GUI/hitomi_downloaded_youtube — 유튜브 다운로드 |
| Obsidian | D:/Obsidian — 원고·노트 |

이 표는 발견을 돕는 과거 등록값이며 매 작업에서 실제 설정을 확인한다. Bridge는 workspace 루트 기준 상대 경로, Lumina 프로젝트는 로컬 절대 경로다. 다른 워크스페이스가 함께 있어도 콘텐츠 작업 대상으로 자동 포함하지 않는다.

작품별 기존 프로젝트를 사용하고 쇼츠는 복사용 시퀀스를 복제한다. 최신 원고·음성·SRT의 이름과 작품/하위 폴더를 연결한다. 원고 기록 위치가 정해져 있으면 해당 Obsidian 노트도 갱신한다. 과거 개인 스킬 스크립트·메모리 경로에 접근할 수 있다고 가정하지 않는다.

소스 이동은 먼저 사용자가 지정한 동일 파일의 실제 경로를 확인한다. 이름이 비슷하거나 화면상 더 적합한 파일로 이동 대상을 대체하지 않는다. 동명 후보가 여럿이면 경로·크기 등으로 식별하고 불명확하면 확인한다. 소스 선정과 파일 정리는 별개다. 이미 목적지에 있으면 재이동하지 않는다.

Bridge `move_file`로 요청한 파일을 이동하고 목적지·원래 경로를 검증한다. 이동 전 Lumina 등록 여부를 확인해 등록된 미디어만 기존 ID로 `media_relink`한다. 파일 이동만 요청받았다면 미등록 파일을 임의로 import하지 않는다. 가져오기만 하고 이동했다고 보고하지 않는다. 파일 정리 중 타임라인을 임의 변경하지 않는다. 프로젝트 `.lumina`는 외부 파일 쓰기로 수정하지 않는다.

## 3. 대본·캡션·그래픽과 음성 정렬

먼저 현재 문구·분할·ID·트랙 스타일과 실제 내레이션 트랙을 읽는다. 화면에 보이는 자막 수를 하드코딩하거나 예전 Phrase 프로젝트의 문구를 최신 원고로 취급하지 않는다.

| 목적 | 도구 / 모드 |
|---|---|
| 런타임 확인 | speech_status |
| 새 음성 받아쓰기 | speech_start, mode=transcribe |
| 작성한 대본 줄을 음성에 정렬 | text_set_script 후 speech_start, mode=script |
| 기존 트랙·스타일을 유지해 음성 정렬 및 자막 후처리 | speech_start, mode=retime, 대상 caption_track_ids |
| 진행·결과 확인 | speech_list / speech_job |
| 검수한 결과 반영 | speech_apply |
| 취소 | speech_cancel |

`speech_start`에 실제 `sequence_id`, `audio_track_id`를 지정한다. 롱폼은 shorts=false, 쇼츠 새 받아쓰기는 shorts=true를 사용한다. 기존 경계는 합치지 않지만 긴 행은 자동 분할될 수 있다. 사용자 확정 경계·문구와 충돌하는지는 preview에서 확인한다. 여러 트랙 중 번역·TMI·보조 설명을 내레이션 자막으로 선택하지 않는다.

선택한 내레이션 트랙의 소스 위치·컷·속도·배치를 반영해 시퀀스 시간축으로 분석한다. Phrase 서버는 필요 없다. 분석은 한국어 음성 정렬이며 글자 수 비례 배분이 아니다. 모델 결과를 프레임 정확도 보증으로 취급하지 않는다.

`speech_job`의 preview는 **아직 타임라인을 바꾸지 않은 결과**다. 전 행의 문구·ID·시간·큰 이동·짧은 자막·겹침을 확인하고 주요 지점은 실제 재생한다. 시간값은 시퀀스 ticks다. 대본/기존 캡션 정렬은 다음 자막 시작까지 앞 자막 끝을 이어 중간 빈 구간을 없앤다.

`speech_apply`는 Undo 가능한 한 번의 적용이다. 입력이 바뀌어 오래된 결과가 되면 적용을 거부하므로 현재 상태를 다시 읽고 필요한 경우 재분석한다. 다른 프로젝트에 적용하지 않는다. 분석 도중 타임라인을 바꿨다면 기존 결과를 무조건 재사용하지 않는다.

**script/transcribe 적용은 새 캡션 트랙을 만든다.** 기존 자막이 있는 상태에서 재정렬하려면 retime을 사용한다. 새 트랙을 만드는 요청이라면 기존 트랙과 동시에 렌더돼 겹치지 않는지 확인하고, 어느 트랙을 유지할지 사용자 지시와 작업 범위에 맞춰 처리한다. 새 트랙 생성 시 기존 스타일이 자동 상속된다고 가정하지 않는다. 대본만 반영하려면 해당 도구의 transcript_only 옵션을 확인한다.

GUI의 자동 문구 반영은 파일 저장이 아니다. 저장은 `save_project` 결과로 확인한다. 음성 미리보기는 현재 앱 실행 세션에 속하고 재시작 후 자동 복구된다고 가정하지 않는다.

### 부분 편집

- `caption_set`: 문구·개별 스타일. 마침표·공백·줄바꿈만 바꾸면 음성 위치 정보 유지, 발음에 해당하는 글자가 바뀌면 무효화.
- `caption_split_text`: 현재 문구를 expected_text, Unicode 문자 위치를 offset으로 지정. 유효한 음성 위치 정보가 없으면 확인한 at을 명시. 문구와 클립을 한 번에 분할.
- `caption_merge_next`: direction=next 또는 previous. 같은 트랙에서 바로 이어지고 스타일·효과가 같은 경우만 병합.
- `graphic_set_layer`: 실제 그래픽의 특정 레이어 수정. 캡션을 그래픽으로 변환해 우회하지 않음.

### 외부 Phrase 이관 이력

현재 실행 경로는 Lumina 내부 speech 도구다. 외부 Phrase의 구형 HTTP/셸 절차는 이관 이력이며 자동 대체 경로가 아니다. 도구 부재 시 현재 런타임·연결을 진단한다.

내레이션 처리의 기존 기준은 Hard Limiter ceiling -4dB, boost 0, look-ahead 7ms, release 100ms다. 오래된 ffmpeg 근사식의 release 200ms와 섞지 않는다. 실제 지원 도구가 없으면 처리한 척하지 않으며 임의 EQ/loudnorm을 추가하지 않는다.

## 4. 배치·복구·검수

편집 전 예상 길이와 실제 길이, V/A 트랙별 클립 수·트랙 수·주요 클립 경계, 변경 대상과 보호할 트랙을 기록한다. 예상과 크게 다른 길이(예: 약 40초 예상인데 913초), 멀리 떨어진 클립, 비정상적인 개수 증감은 원인을 확인한다. 사용자 수동 작업이나 기존 후반 클립일 수 있으므로 자동 삭제·축소하지 않는다. 작업 후 같은 기준으로 비교하여 의도한 변경과 부수 변화를 구분한다. 원인 미확인 이상값이 남으면 정상 완료로 판정하지 않는다.

소스 DB·파일명은 검색 단서이며 실제 화면과 소스 in/out을 확인한다. 배치 전 큐 계획을 쓰고, 정지 이미지·효과음에도 길이를 명시한다. overwrite의 covered 결과와 이웃 클립을 확인하고 의도하지 않은 덮어쓰기는 즉시 Undo/rollback한다.

여러 변경은 작은 transaction으로 묶는다. 도구 이름은 연결된 정의를 확인한다. 시간 초과는 미실행의 증거가 아니므로 클립·미디어·프로젝트·job 목록부터 읽고 중복 import·배치·분석·export를 피한다. TARGET_CHANGED면 대상을 다시 확인한다. GUI 실패를 숨은 헤드리스나 `.lumina` 직접 수정으로 우회하지 않는다.

구형 `editor.status UNKNOWN_METHOD`는 과거 Bridge의 liveOnly 중계 계층에서 발생했다. 현행 연결은 Lumina의 GUI 우선 MCP를 써야 한다. 이 기록만 보고 설정을 무조건 바꾸지 말고 실제 정의·버전·상태를 확인한다.

완료 보고는 프로젝트 경로·시퀀스·변경 범위·저장 성공·실제 검수 범위·미해결을 담는다. 내보내기를 요청받으면 작업 done과 출력 파일·코덱·길이를 확인한다. FFprobe·이미지 표본·GUI 엔진 연결 성공은 전체 재생·청취·창 가시성을 보장하지 않는다. 예전 테스트의 프로젝트명·dirty·시퀀스 수를 현재 상태로 재사용하지 않는다.


## 연속 프레임 검수 — 2026-10-31 추가

Bridge의 lumina_list_tools에서 inspect_source_frames, inspect_timeline_frames의 실제 정의를 조회한 뒤 lumina_call_tool로 호출한다. 로컬 Lumina MCP에 구현되므로 기존 MCP 프로세스는 재연결해야 한다. GUI 재설치는 필요 없다.

- 원본: `inspect_source_frames({path, start_frame, count:12, step:1})`. 실제 이미지, 0기준 표시 순서 프레임 번호, PTS, RGB 변화량. 최대 24장, 시트당 6장. EOF로 부족하면 complete=false, 범위 밖이면 오류. 정확한 번호를 위해 파일 처음부터 디코딩하므로 긴 파일은 시간 초과할 수 있다.
- 합성: `inspect_timeline_frames({sequence_id, start_frame, count:12})`. 명시한 시퀀스의 연속 합성 프레임, ticks, timecode. 소스 번호를 그대로 넣지 않는다. 검사 중 프로젝트/타임라인이 바뀌면 결과를 폐기한다.
- 예: 시퀀스 300번 프레임에서 새 컷이면 start_frame=294, count=12로 294~305 확인. [in,out)에서 299는 이전 컷 마지막, 300은 다음 컷 처음이다. 소스와 시퀀스의 fps/속도 매핑은 별도 확인.
- step>1은 표본이며 1프레임 혼입 없음의 증거가 아니다. 변화량은 샷·인물·결함 판정 점수가 아니다. complete=true도 품질 통과를 뜻하지 않는다.
- DB 후보 → 실제 소스 범위 훑기 → 양 끝/의심 위치 연속 프레임 → 의미·음성 기준 배치 → 합성 경계 → 정상 속도 시청 순으로 검수한다. 혼입/인지 시간/끝무렵 동작 분류는 편집 문법을 따른다. 도구 자체는 자동 트림/배치를 하지 않는다.
- 영상·음성을 실제로 볼/들을 수 없는 환경이면 리듬·동작 완료·청취는 미검수로 남긴다. 정지 프레임으로 정상 속도 검수를 대체하지 않는다.


## 자막 자동 후처리와 적용 검수 — 2026-11-01

현행 Lumina는 모든 speech 모드의 preview에서 첫 자막 0프레임, 연속 구간 연결, 끝 쉼표/마침표 정리, 긴 행의 음성 문장·절 경계 분할을 자동 수행한다. 기존 경계를 합치지는 않지만 긴 행은 나뉘며 첫 조각만 원래 ID를 유지한다. retime은 원래 트랙·스타일을 보존한다. script/transcribe는 새 캡션 트랙을 만든다.

1. 분석 전 최신 본 자막·내레이션·확정 분할과 명시한 무자막 인트로를 기록한다.
2. preview의 `caption_quality=gapless-clean-split-v1`과 `quality_warnings`를 확인한다. 이 표식이 없으면 구버전 결과로 보고 자동 처리됐다고 가정하지 않는다.
3. 전 행의 문구·시간·원래 ID/새 ID·과분할·고유명사·공백·겹침을 검수한다. 안전한 경계가 부족한 긴 행은 경고로 남으므로 실제 음성에 근거해 보정한다. 글자 수 비례 시간 배분은 금지한다.
4. 첫 0프레임 처리가 첫 발화 누락을 숨기지 않는지 확인한다. 명시한 무자막 인트로나 시간만 변경하라는 요청이 있으면 자동 결과와 충돌할 수 있다. preview를 그대로 적용하지 말고 지원하는 개별 편집으로 요청 범위를 지킨다. 존재하지 않는 예외 옵션을 만들어 호출하지 않는다.
5. 적용 후 본 자막 개수·변경 ID를 다시 읽고 연결된 TMI를 관련 본 자막 하나에 맞춘다. 롱폼 3.5초 초과 전수 검토, 5초 초과/여러 문장 우선 분할 검토를 하되 균등 분할하지 않는다. 처음·분할 경계·최장 구간·끝의 합성과 실제 음성을 검수한다.
6. 저장 성공과 첫 시작 프레임, 공백/겹침/제거 대상 종결부호 수, 분할 전후 개수, 최장 구간·유지 예외, 미청취 여부를 보고한다. 자동 처리 성공만으로 품질 완료라 하지 않는다.

Phrase 서버·옛 프로젝트·외부 SRT 왕복으로 자동 우회하지 않는다. 내부 도구 실패는 런타임/연결을 진단한다. 기존 저장 자막은 앱 실행만으로 바뀌지 않으며 새 분석의 검수된 preview를 적용해야 한다.
