# Lumina 텍스트 패널

2026-10-31. 대본·캡션·그래픽을 구분하고 음성 분석을 Lumina 내부 작업으로 실행한다. Phrase Studio HTTP 서버, Bridge, Phrase 프로젝트 파일에 의존하지 않는다.

## 사용

- **캡션:** 모든 캡션 트랙을 시간순으로 표시한다. 각 행에 V번호·트랙 이름·시작/끝이 나오며 트랙 필터와 검색을 함께 사용할 수 있다. 잠긴 트랙은 읽기만 가능하다.
- **그래픽:** 영상 트랙의 텍스트 레이어를 나열하고 편집한다. 그래픽 자막과 실제 캡션은 서로 다른 탭에 있다.
- **대본:** 시퀀스에 별도로 저장된다. 영상에 자동 표시되지 않는다. 빈 대본에 모든 캡션의 문구를 가져오거나 새 대본을 입력할 수 있다. 대본 한 줄은 음성 정렬 시 자막 한 개다.
- 자막 문구 중간에 커서를 두고 **Enter / 커서에서 분할**을 누르면 문구와 클립을 함께 분할하고 다음 자막 첫 커서로 이동한다. Shift+Enter는 자막 안에서 강제 줄바꿈이다. 기존 스타일·효과를 유지하며 한 번의 Undo로 분할을 되돌린다.
- 음성 정렬 정보가 있으면 커서에 대응하는 음성 시점을 사용한다. 없으면 재생헤드를 자막 안에 두거나 ‘분할 초’를 지정한다. 글자 수 비례로 시간을 만들지 않는다. 분할 시간 입력을 직접 바꾸면 그 시간을 우선한다.
- ‘병합’은 같은 트랙에서 바로 이어지고 스타일·효과가 같은 다음 자막과 합친다. 스타일이 다르면 조용히 버리지 않고 거부한다.
- 자막 맨 앞에서 선택 영역 없이 Backspace를 누르면 이전 자막과 병합하고 연결 지점으로 커서를 이동한다. 병합 조건은 위와 같다.
- 문구 수정은 잠깐 입력을 멈추면 자동 반영된다. 별도 확인이나 포커스 이동이 필요 없다. 마침표·띄어쓰기·줄바꿈만 바꾸면 음성 정렬 정보를 유지한다. 발음에 해당하는 글자를 바꾸면 해당 정렬 정보는 무효화된다. 프로젝트 파일 저장은 별도다.
- 시간 표시를 누르면 프로그램 모니터가 해당 시점으로 이동한다. 프로그램 재생 중에는 현재 자막이 목록 상단으로 따라오며 입력 커서를 빼앗지 않는다. 한글 조합 중 Enter는 분할하지 않는다.

## 내부 음성 작업

1. 내레이션 오디오 트랙을 고른다. 해당 트랙의 실제 클립 배치·소스 in/out·속도·음량을 반영해 **시퀀스 시간축의 음성**을 만든다. 다른 오디오 트랙은 분석용 복사본에서만 음소거한다. 원본 타임라인은 바꾸지 않는다.
2. 대본이 비어 있으면 받아쓰기, 대본이 있으면 해당 줄 구성에 음성 정렬, 캡션 탭에서는 최신 캡션 문구·ID를 보존한 재정렬을 실행한다. 캡션 필터가 ‘모든 트랙’이면 모든 캡션 트랙이 대상이다.
3. Whisper large-v3와 한국어 CTC로 발화 위치를 구한다. 분석은 별도 프로세스에서 실행되어 편집기를 막지 않는다. 롱폼/쇼츠 분할은 받아쓰기에 사용하며, 기존 자막 재정렬은 사용자가 정한 줄을 보존한다. 대본 정렬과 기존 자막 재정렬은 앞 자막의 끝을 다음 시작에 연결해 자막 사이 빈 구간을 없앤다. 엔진은 첫 발화 이전과 마지막 발화 이후까지 자동 확장하지 않는다. 이는 구현 설명이며 최종 편집 정책이 아니다. [자막 완료 기준](editing-grammar/caption-quality.md)에 따라 일반 영상 첫 자막은 0프레임으로 별도 보정하고, 문장부호·과병합·공백을 검수한다. retime은 이 후처리를 자동 수행하지 않는다.
4. 결과 문구와 시작/끝, 이전 시각 대비 이동량을 미리 본다. **미리보기는 편집 완료가 아니다.** 적용 전 정상 속도에서 음성을 확인한다. 모델 정렬은 정확도를 보장하지 않는다.
5. 받아쓰기·대본 정렬은 대본만 적용하거나 대본과 새 캡션 트랙을 함께 만든다. 재정렬은 기존 캡션의 시간만 갱신한다. 적용은 Undo 가능하다.
6. 분석 중 타임라인·대본·미디어가 바뀌면 오래된 결과를 거부한다. 프로젝트가 바뀌어도 다른 프로젝트에 적용하지 않는다. 미리보기는 현재 실행 세션에 속하며 편집기를 재시작하면 다시 분석해야 한다. 작업 디렉터리에 진단용 JSON/로그/음성이 남는다.

처음 통합 범위는 한국어다. 재정렬 대상 트랙들이 서로 겹치지 않으면 전체 발화 순서로 함께 정렬한다. 동시에 겹치는 자막 트랙은 각 트랙을 별도로 정렬하므로, 번역·보조 설명 트랙을 내레이션 자막처럼 선택하지 않는다.

## 런타임과 배포

음성 알고리즘은 `engine/lumina/speech/` 안에 있다. `worker.py`와 알고리즘 파일을 설치본에도 데이터로 포함한다. 모델 라이브러리는 일반 편집 엔진과 별도 환경에서 실행한다.

Python 경로 우선순위: `LUMINA_SPEECH_PYTHON` → `LUMINA_HOME/speech-runtime/Scripts/python.exe` → 개발 폴더 `engine/.speech-venv/Scripts/python.exe`. 이 PC의 설치본은 `D:/Dev/lumina/engine/.speech-venv`도 탐색한다.

모델은 `LUMINA_SPEECH_MODELS`, 기본 `~/.lumina/models/speech`, 이 PC에서는 `D:/Dev/lumina/.speech-models`를 사용할 수 있다. 모델이 없으면 첫 실행에 다운로드가 필요하다.

이 PC는 `tools/migrate_speech_runtime.py D:/Dev/phrase-studio`로 기존 모델·라이브러리를 Lumina 전용 폴더에 이관했다. 같은 드라이브의 파일은 하드링크를 사용해 대용량 파일을 중복 저장하지 않는다. **원본 폴더 삭제 후에도 Lumina 쪽 파일은 유지된다.** 링크된 환경을 제자리에서 pip 업그레이드하지 말고 새 가상환경을 만들어 교체한다. 기본 Python 3.14의 공용 라이브러리도 사용하므로 Python 자체는 필요하다. Phrase 앱·서버·프로젝트 데이터는 복사하지 않았다. 기존 앱 삭제는 수행하지 않는다.

다른 PC는 별도 Python 환경에 `engine/lumina/speech/requirements.txt`를 설치하고 `LUMINA_SPEECH_PYTHON`을 지정한다. GPU 사용 시 해당 PC에 맞는 PyTorch/CUDA 빌드를 사용한다. CPU도 지원하지만 느리다.

## MCP

일반 텍스트 편집은 registry 명령이 그대로 MCP에 노출된다.

- `caption_split_text`, `caption_merge_next`, `text_set_script`
- `speech_status`, `speech_start`, `speech_list`, `speech_job`, `speech_cancel`, `speech_apply`

`speech_start`는 `sequence_id`, `audio_track_id`, `mode=transcribe|script|retime`, 선택적 `caption_track_ids`, `shorts`를 받는다. `speech_job`의 결과 시간은 시퀀스 ticks이며 모든 행을 검수한 뒤 `speech_apply`를 호출한다. Chat은 기존 Bridge의 `lumina_list_tools` / `lumina_call_tool`로 이 도구들을 사용한다. `.lumina` 직접 수정이나 별도 Phrase 파일 동기화는 필요하지 않다.


## 2026-11-01 자동 자막 후처리

내부 speech 결과를 preview로 내보내기 전에 첫 자막 0프레임 시작, 연속 구간 연결, 끝 쉼표/마침표 제거, 긴 자막의 음성 문장/절 경계 분할을 자동 수행한다. 받아쓰기·script·retime 모두 적용한다. 기존 자막 재정렬에서도 과병합을 나눌 수 있으며 원래 트랙·스타일을 보존하고 첫 조각은 원래 ID, 나머지는 새 ID다. 모든 변경은 preview 적용 시 한 번의 Undo로 복구된다.

문장 중간 문장부호·소수점·물음표·느낌표·말줄임표·URL·영문 점 약어는 보호한다. 현재 분할은 문장부호와 한국어 절 종결 패턴에 기반한 보수적인 규칙이다. 문맥을 완전히 이해하는 분할기는 아니며 음성 경계가 없는 긴 자막은 quality_warnings에 남기고 GUI에서 검수 경고를 표시한다. 사용자 문구를 다시 쓰거나 시간을 글자 수로 추정하지 않는다. 설치된 새 버전에서 실행한 새 분석부터 적용하며 기존 작업과 타임라인을 자동 변경하지 않는다.
